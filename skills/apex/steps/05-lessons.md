## Contract

`bash skills/apex/scripts/grep-lessons.sh <project-root> <term1> [<term2> ...]` reads `<project-root>/.claude/lessons-index.md` + `lessons.md` for keywords **extracted deterministically from `hypothesis.goals[]`** (same recipe as step 6: lowercase + tokenize + drop stopwords + drop <4-char tokens + dedupe; cap at top 8 by document-order). Same `goals[]` -> same keyword set. **Screener gate (K=25)**: when grep output is `<= 25` lines, orchestrator reads matches inline (no Haiku hop) and derives `kept[]` itself by relevance to `hypothesis.goals[]`. Exception: if the raw grep blob is already in orchestrator context (step 4/5 inline-skip read lessons directly) OR `{session}-discovery-skip.json` exists with non-empty `inlined_paths`, screen inline regardless of the `> 25` threshold AND swap the grep keyword set to `inlined_paths` basenames before re-greping; empty narrowed-grep -> skip the screener pass entirely (the blob already entered working memory; screener adds marginal signal when inlined paths pin the surface). When grep output is `> 25` lines, spawn `agents/lesson-screener.md` (Haiku, single call; raw output + hypothesis explicit in spawn prompt) -> `.claude-tmp/apex-active/{session}-lesson-screened.json` (producer-validated against `lesson-screened.schema.json`). **Truncation re-run gate**: when the screener returns its one-line status with the `truncated=true` suffix (raw grep input hit the line cap, body slices beyond the cap were dropped), the orchestrator MUST re-run `grep-lessons.sh` ONCE with a halved keyword set (top 4 by document-order rather than top 8) and re-spawn the screener with the narrower input BEFORE consuming `kept[]`; further `truncated=true` after the retry -> proceed with what was kept and surface a `lessons-truncation-persistent` note in working memory for `/apex-improve` to act on. Closes the 3-session cluster where `truncated=true` was advisory only and the orchestrator proceeded with a partial slice. The screener emits `kept[]` as `{line_range, section_title, screener_reason}` ranges ONLY (NEVER verbatim bodies - body re-emission from the cold Haiku context was ~81% of step-5 wall); the orchestrator then materializes bodies deterministically off the Haiku path via `bash skills/apex/scripts/slice-lessons.sh <project-root>/.claude/lessons.md <kept line_range...>` and back-fills `kept[].content` for the downstream-spawn role. The raw grep blob never enters working memory. The inline path (`<= 25` lines) already holds bodies from its own inline read, so it writes `kept[].content` directly (no slice call). Either path then runs `bash skills/apex/scripts/update-hit.sh <project-root>/.claude/lessons.md <line>...` for kept line ranges only. Tolerate empty grep output (no `lessons-index.md` -> silent skip; screener / inline pick also skipped). Project-context cached from step 1. Working memory propagates kept lessons + matched paths + project context to steps 6 / 8 / 9 / 10 / 11 - **pre-filtered to the `hypothesis.goals[]` axis** before propagation: a kept block is retained for its on-axis signal, not its whole body, so off-axis markers co-located in that block (unrelated nouns the screener could not separate at grep/section granularity) are dropped before they enter step-6 inline-read or downstream working memory (token discipline; ~100-200 tokens/run of kie/reconcile/epoch context carried into discovery unfiltered). When a kept lesson confirms a `hypothesis.goals[]` entry is **already satisfied** in current code (a prior fix already landed), record that goal as pre-satisfied: step 6 narrows `allowed_files` by dropping that goal's deterministic noun set, and step 8.2 marks the goal `already-satisfied` without dispatching an executor (step-5 lessons early-detection saved a redundant dispatch - promote the signal to a scope-refinement gate, not just a step-5 observation).
