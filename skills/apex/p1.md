## p1.0 Initialisation

### Step 1: Validate preflight artifact

Read `.claude-tmp/scout/preflight-{session}.json` and decide branch:

```
preflight=".claude-tmp/scout/preflight-{session}.json"
if [[ ! -f "$preflight" ]]; then
  branch=absent
elif PYTHONPATH="$HOME/.claude/skills/apex/scripts" python3 -c "
import sys
from _validate import consumer_load
sys.exit(0 if consumer_load('$preflight', 'preflight') is not None else 1)
" 2>/dev/null; then
  branch=valid
else
  branch=invalid
fi
```

| Branch | Action |
|--------|--------|
| `absent` | trivial / zero-layer - `implement.md` proceeds with NO findings consultation |
| `valid` | medium - `implement.md` consults `screened-{session}.json` before dispatch |
| `invalid` | HARD ABORT with explicit error to user (downstream-pipeline failure signal); run `scripts/session-end-hook.sh {session}` inline; do NOT silently fall through |

### Step 2: Mode-specific setup

**Main mode (`MODE=main`):**

```
# 2a. Capture working-tree baseline (consumed by p1.1b polish, p1.3 tail, p1.4 reflector)
bash $HOME/.claude/skills/apex/scripts/apex-baseline.sh {session}

# 2b. Concurrent-apex conflict check; stdout = "<file> -> <scope-basename>" per overlap
overlap=$(bash $HOME/.claude/skills/apex/scripts/apex-conflict-check.sh {session}); rc=$?
```

Dispatch on `$rc`:
- `0` - no overlap; proceed.
- `1` - overlap detected (list in `$overlap`). AskUserQuestion (header: "Concurrent apex"; options: `abort`, `proceed-anyway`; dismiss/cancel = abort).
  - abort -> run `scripts/session-end-hook.sh {session}` inline; exit cleanly.
  - proceed-anyway -> pre-dirty files are processed normally per "process as normal file" rule (staged, polished, committed alongside apex-introduced edits).
- `2` - script-side failure (bad args, missing `git`, missing `jq`); stderr carries the cause. Surface to user, run `scripts/session-end-hook.sh {session}` inline, exit. Do NOT treat as overlap.

**Teammate mode (`MODE=teammate`):**

Skip 2a + 2b (p2.0 owns baseline + conflict check; both shared by all teammates).

Write the scope-check pointer for the teammate's own Claude Code session:

```
pointer_dir=".claude-tmp/apex-active/{session}-scopes"
mkdir -p "$pointer_dir"
printf '%s\n' "$(realpath .claude-tmp/apex-active/{session}-{teammate-id}-scope.json)" \
  > "$pointer_dir/{teammate_cc_session_id}.txt"
```

The teammate's `cc_session_id` is the new Claude Code session id for the spawned `TeamCreate` teammate (distinct from the main / p2 session).

### Step 3: TaskCreate downstream chain

Each line below is one `TaskCreate(subject, description)`. Tasks run in TaskCreate order; `TaskCreate` has no `blockedBy` parameter. The chain is sequential by construction. Orchestrator marks each task `in_progress` when dispatching its per-step skill / script and `completed` on clean return (mirrors `apex-lessons/analyze.md` Step 0b). Stale-task reminders mid-run indicate this contract was missed.

Templates use `(skill.md ...)` to indicate dispatch shape. A bare `(skill.md)` means the skill runs inline on the orchestrator (no subagent). A skill with `-> agents/<name>.md` MUST spawn that subagent - the orchestrator NEVER does the agent's work inline. p1.1 is the canonical case: `implement.md` is dispatch-only and forwards every code modification to `agents/executor.md`. Reading the skill body without honouring its `-> agents/...` arrow is a framework violation (see `implement.md` "Hard rule: dispatch only").

**Main mode:**

```
TaskCreate "p1.1 Implement"             (implement.md -> agents/executor.md per task; dispatch-only - orchestrator MUST NOT inline-Edit slice files)
TaskCreate "p1.1b In-scope polish"      (polish.md - inline on host model)
TaskCreate "p1.2 Verify + fix"          (verify-fix.md --phase p1 -> scripts/verify-build.sh + agents/executor.md)
TaskCreate "p1.3 Tail (learn/docs/git)" (tail.md --phase p1 -> scripts/detect-tail-mode.sh + agents/{learn,documentation,git}.md)
TaskCreate "p1.4 Self-reflect"          (reflect.md --phase entryflow+p1 -> scripts/reflect-traces.sh + agents/reflector.md)
TaskCreate "p1.5 Cleanup"               (scripts/cleanup-session.sh)
TaskCreate "p1.6 Inline summary"        (summary.md --phase p1 - inline; reads {session}-hypothesis.json)
```

**Teammate mode** (skips p1.2, p1.4, p1.5 - central p2.3 / p2.5 / p2.6 own these):

```
TaskCreate "p1.1 Implement"             (implement.md -> agents/executor.md per task; dispatch-only - orchestrator MUST NOT inline-Edit slice files)
TaskCreate "p1.1b In-scope polish"      (polish.md - inline on host model)
TaskCreate "p1.3 Tail (docs only)"      (tail.md --phase teammate -> agents/documentation.md only)
TaskCreate "p1.6 Inline summary"        (summary.md --phase teammate - inline; reads {session}-{teammate-id}-task.md)
```
