# /apex

Main session orchestrator. Full behavioral contract: `apex-core.md`. Light-read skeleton + skip matrix: `apex-core-overview.md`.

## Step 0: queue tasks

```
TaskCreate "1.  Analyze + read project-context.md"
TaskCreate "2.  Create session manifest"
TaskCreate "3.  Trivial pre-flight"
TaskCreate "4.  Hypothesis"
TaskCreate "5.  Load lessons"
TaskCreate "6.  Discovery"
TaskCreate "7.  Economy pre-flight"
TaskCreate "8.  Execute"
TaskCreate "9.  Polish"
TaskCreate "10. Verify"
TaskCreate "11. Tail (documentation [+learn])"
TaskCreate "12. VERSION bump + git sync"
TaskCreate "13. Self-reflect"
TaskCreate "14. Cleanup session"
TaskCreate "15. Inline summary"
```

All 15 always queued. Trivial branch at step 3 marks 4-13 completed-skipped.

## Tier matrix

| Tier     | Decided at | Effect                                                                                                  |
|----------|------------|---------------------------------------------------------------------------------------------------------|
| trivial  | step 3     | Step 3.1 inline `Edit` / `Write` -> jump to 14. Skips 4-13.                                             |
| economy  | step 7     | Step 8 executors run on Sonnet; step 9 polish skipped; step 11 skips `learn`.                           |
| standard | step 7     | Step 8 executors run on the main session model; full tail (step 9 polish + step 11 documentation always run; learn runs when the difficulty gate holds - no tier-conditional skip path under standard). |

Step 13 reflector is **background** in non-trivial paths (economy + standard); the reflector owns the post-reflect `cleanup-session.sh --post-success` call as its final action. Step 14 only runs on the trivial path (where step 13 was skipped).

## Step contracts (terse)

1. **Analyze** - inline. AskUserQuestion if ambiguous; abort = clean exit (no manifest yet, skip session-end-hook). Read `<project-root>/docs/project-context.md` (best-effort; absent = silent skip; cached for downstream; cap read at ~200 lines). When formulating the working interpretation, expect step 4 to emit a `goals[]` decomposition: single-task prompts -> one goal; multi-task / audit prompts ("make sure all X are properly Y") -> N enumerated goals. Internal bias only; no user-visible change at step 1.
   - **Early scope narrowing.** When the original prompt implies a multi-phase plan (>3 implied phases, OR >5 enumerated subtasks, OR explicit phase / step / roadmap language, OR architectural-refactor verbs that predictably touch `docs/architecture/**` / `CLAUDE.md` / VERSION - rate-limit, middleware, schema-migration, breaking-API, env-var addition, new-locale registration - OR feature work that modifies documented UI / behavior, predictably touching `CLAUDE.md` / `docs/features/**` / `.claude/rules/**`), AskUserQuestion BEFORE step 4 to narrow scope (`audit-only` | `phase-1-only` | `full-scope` | `code-only-no-docs` | `let-me-respec`); do NOT defer to a step 8 re-conversation after goals are drafted (reflector 9dd0d177: "Step 8 scope re-conversation happened late; pre-run conversation could surface this earlier"). Cheaper to narrow once at step 1 than to discard a 6-goal hypothesis at step 8. The `code-only-no-docs` option pre-coordinates the full doc-touch surface so `docs/**` + `CLAUDE.md` + `.claude/rules/**` + VERSION edits enter `allowed_files` up-front rather than surfacing post-dispatch as scope drift - the step-11 documentation agent then needs no mid-tail `allowed_files` expansion and step-12 git-stage no longer strands legitimate doc edits (reflector 006ab516, 94c44d6c, 87c0386e, 7fd94f70, 93bb9c68, e1c1a00e, dd1b88c5, 6f0b89ce: VERSION auto-bump + docs/**/*.md + CLAUDE.md + .claude/rules/*.md recurrently appended outside `allowed_files`).
   - **Review-only hypothesis-shape.** When the prompt names review / audit / check / verify verbs WITHOUT explicit edit verbs ("review my X", "audit Y", "check Z is correctly used"), tag the working interpretation `review-only` and AskUserQuestion to disambiguate intent (`report-only` | `edit-to-fix-found` | `edit-only-if-asked`). Default to `report-only` on dismiss. The chosen mode threads through step 4 hypothesis (carry `mode` field) and step 8 (skip executor entirely under `report-only`; gated executor under `edit-only-if-asked`). Reflector b69d28ba: "review-only workflows need upfront clarification". Under `report-only`, pre-seed the declared deliverable output path named in `original_prompt` (`*-audit.md` / `*-report.md` / `*-findings.md`) into `allowed_files` at scope-finalization (mirrors `code-only-no-docs` pre-coordination so the scope-check hook does not block the deliverable write), and emit a lightweight `{session}-traces/report-only-findings.md` capturing the classification / ETL output so the run is auditable beyond the dispatch-summary `notes` field (reflector 5ec98cfc, 33935c17).
   - **Deploy-doc preload.** When `original_prompt` names deploy / wiring verbs (`deploy`, `docker-compose`, `migrate`, `seed`, `sidecar`, `wire`, `wiring`, `integration`), additionally read `<project-root>/docs/integration.md` (or `docs/deploy.md` / `DEPLOY.md` / `INSTALL.md` - first hit wins; best-effort; absent = silent skip; cap ~200 lines) before step 4 hypothesis emission. Closes the gap where hypothesis drafts against assumed-unwired components when the deploy chain is already wired (reflector 923ee3f7: seeder hypothesis assumed unwired but migrate sidecar already ran db:seed + litellm:ingest; the gap surfaced only at step 8 audit).
   - **Plan-completed early-exit.** When `original_prompt` is a `continue: <plan-file>` whose top-level goals are all `[x]` / DONE, AskUserQuestion BEFORE step 2 (`close-plan-nothing-to-do` | `narrow-to-explicitly-deferred-items` | `re-spec`; dismiss = close, clean exit, no manifest). For a stale-looking plan status section, run the plan's encoded acceptance tests as the satisfiability proof - field-presence is insufficient. Fixes the continue-form prompt-hash non-convergence the step-13 guard otherwise catches only post-hoc (reflector ff441791 / f5d3280a / 4c92e825 / b2716ff4 / 35b42f2b / 2c226d56).
2. **Session manifest** - `bash skills/apex/scripts/create-session.sh --cc-session-id "$(bash skills/apex/scripts/get-cc-session-id.sh)"`.
   - exit 0: `{session}` token to stdout; manifest written + producer-validated.
   - exit 10: stale-only -> auto-cleanup-and-proceed (`bash skills/apex/scripts/session-end-hook.sh <stale-token> --foreign` per stale; re-run create-session). Active-detected -> AskUserQuestion (`abort` | `proceed alongside` | `cleanup-stale-and-proceed`); dismiss/cancel = abort. On abort with no manifest: skip session-end-hook and exit cleanly. On `proceed alongside`, after step 6 scope is finalized compare this session's `allowed_files` against each live sibling's `.claude-tmp/apex-active/*-main-scope.json` and surface a file-level-overlap warning when any path is shared - authorized co-running does NOT imply disjoint file sets, and a concurrent same-file edit only avoided a clobber by commit-order luck (reflector f3915610).
3. **Trivial pre-flight** - inline. Trivial = ALL of: single file edit (or single new file) AND file path explicitly named in `original_prompt` AND no new public symbol / endpoint / component AND no cross-file dependency. ANY ambiguity = non-trivial.
   - **Verb-pattern relaxation**: when `original_prompt` matches `/^\s*(rename|format|fix typos?|reword|add (a )?comment|remove (a )?comment|update copy|update string)\b/i`, the path-naming requirement is relaxed: if the prompt does not name a path explicitly, a single inline `Glob` for the most specific noun in the prompt is allowed - exactly one match qualifies (zero or 2+ = non-trivial). All other trivial constraints (no new public symbol / no cross-file dep / ANY ambiguity disqualifies) still apply. Pushes pure edit-only prompts onto the 4-13-skip rail.
   - **3.1** (trivial only): inline `Write` of `{session}-main-scope.json` (`allowed_files = [<the single file>] + safety paths`) + scope-check pointer at `.claude-tmp/apex-active/{session}-scopes/{cc_session_id}.txt`. Inline `Write` of minimal hypothesis stub (`original_prompt` verbatim; `hypothesis` = one-line restatement; `complexity_hint = "low"`; `alternatives = [{interpretation: original_prompt, status: "kept", reason: "trivial path"}]`; producer-validate via `bash skills/apex/scripts/validate-json.sh hypothesis.schema.json <path>`). Inline `Edit` / `Write` of the target. Jump to step 14.
   - Trivial trade-off: skips verify (10), commit (12), reflect (13). User owns lint/build + `git add+commit` afterwards.
4. **Hypothesis** - inline emit. `original_prompt` (verbatim; do NOT paraphrase) + `hypothesis` (1-2 sentences) + `complexity_hint: low|medium|high` + `alternatives: [{interpretation, status: kept|rejected, reason}]` (1-3 entries; minItems: 1) + `goals: [string]` (1..N items; each a discrete actionable check or task; free-text 1-3 sentences. Single-task prompts: one goal verbatim. Multi-task / audit prompts: enumerate one goal per discrete check). `goals.length` drives downstream behaviour at step 6 (top-K), step 7 (deterministic tier rule), step 8.2 (per-goal task split), step 13 (non-convergence detection), step 15 (per-goal summary). For `discovered_paths` only: when `original_prompt` has no path tokens AND `complexity_hint != "low"`, spawn a small Explore subagent (`Agent(subagent_type: "Explore")`) to gather candidate paths; the subagent returns ONLY validated repo-relative paths (existing on disk). Otherwise persist `discovered_paths` empty/absent. Write to `.claude-tmp/apex-active/{session}-hypothesis.json`; producer-validate via `bash skills/apex/scripts/validate-json.sh hypothesis.schema.json <path>`. Validation failure = abort with explicit error.
5. **Load lessons + project docs** - `bash skills/apex/scripts/grep-lessons.sh <project-root> <term1> [<term2> ...]` reads `<project-root>/.claude/lessons-index.md` + `lessons.md` for keywords **extracted deterministically from `hypothesis.goals[]`** (same recipe as step 6: lowercase + tokenize + drop stopwords + drop <4-char tokens + dedupe; cap at top 8 by document-order). Same `goals[]` -> same keyword set. **Screener gate (K=25)**: when grep output is `<= 25` lines, orchestrator reads matches inline (no Haiku hop) and derives `kept[]` itself by relevance to `hypothesis.goals[]`. Exception: if the raw grep blob is already in orchestrator context (step 4/5 inline-skip read lessons directly), screen inline regardless of the `> 25` threshold - the blob already entered working memory so the Haiku hop adds only a round-trip + 120-line truncation. When grep output is `> 25` lines, spawn `agents/lesson-screener.md` (Haiku, single call; raw output + hypothesis explicit in spawn prompt) -> `.claude-tmp/apex-active/{session}-lesson-screened.json` (producer-validated against `lesson-screened.schema.json`). The screener emits `kept[]` as `{line_range, section_title, screener_reason}` ranges ONLY (NEVER verbatim bodies - body re-emission from the cold Haiku context was ~81% of step-5 wall in run 6b038dd5); the orchestrator then materializes bodies deterministically off the Haiku path via `bash skills/apex/scripts/slice-lessons.sh <project-root>/.claude/lessons.md <kept line_range...>` and back-fills `kept[].content` for the downstream-spawn role. The raw grep blob never enters working memory. The inline path (`<= 25` lines) already holds bodies from its own inline read, so it writes `kept[].content` directly (no slice call). Either path then runs `bash skills/apex/scripts/update-hit.sh <project-root>/.claude/lessons.md <line>...` for kept line ranges only. Tolerate empty grep output (no `lessons-index.md` -> silent skip; screener / inline pick also skipped). Project-context cached from step 1. Working memory propagates kept lessons + matched paths + project context to steps 6 / 8 / 9 / 10 / 11 - **pre-filtered to the `hypothesis.goals[]` axis** before propagation: a kept block is retained for its on-axis signal, not its whole body, so off-axis markers co-located in that block (unrelated nouns the screener could not separate at grep/section granularity) are dropped before they enter step-6 inline-read or downstream working memory (token discipline; reflectors 4f6c2f9c / 07c0c53c: ~100-200 tokens/run of kie/reconcile/epoch context carried into discovery unfiltered). When a kept lesson confirms a `hypothesis.goals[]` entry is **already satisfied** in current code (a prior fix already landed), record that goal as pre-satisfied: step 6 narrows `allowed_files` by dropping that goal's deterministic noun set, and step 8.2 marks the goal `already-satisfied` without dispatching an executor (reflector 2b862aab cross-session: step-5 lessons early-detection saved a redundant dispatch in c3db7fce / 85268c23 / a878b37d - promote the signal to a scope-refinement gate, not just a step-5 observation).
6. **Discovery** - agent `agents/discoverer.md` (Sonnet). Cascade-empty -> agent returns `{cascade_empty: true}`; orchestrator runs AskUserQuestion (`abort` | `proceed-with-discovered-or-prompt-paths`); dismiss/cancel = abort. Both empty -> abort runs `session-end-hook.sh` inline.
   - **Inline-skip path** (high-confidence shortcut): when the orchestrator decides at step 4/5 to skip the discoverer subagent and inline Read/Grep itself (hypothesis already names paths + paths validated on disk + lessons hits cover the surface), it MUST still produce `{session}-main-scope.json` + scope-check pointer AND write `.claude-tmp/apex-active/{session}-discovery-skip.json` with `{reason: "<one-line>", inlined_paths: ["<repo-relative>", ...], skipped_layers: ["lsp"|"glob"|"grep"|"screener"]}` so `/apex-improve` can audit gate effectiveness (reflector 58d445eb: "log the skip reason for /apex-improve to tune discovery gates"). **Before writing `{session}-main-scope.json` on this path, reconcile `inlined_paths` against the step-4 hypothesis `discovered_paths` AND the step-8.2 plan-implied write targets**: append every plan write-target not yet in `inlined_paths`, and drop inlined paths no goal/plan-target references (read-only context, not scope), so the skip path neither under-populates `allowed_files` (forcing a step-12 expand) nor over-populates it (reflector 606d3abb: inlined controller never touched; dfbc9eed: 6 inlined vs 9 plan paths). Cache write is also skipped on the inline path (no cascade result to memoize).
7. **Economy pre-flight** - inline **deterministic rule** (no AI emit, no subagent). Inputs: `{session}-hypothesis.json` (`goals`), `{session}-main-scope.json` (`allowed_files`).
   ```
   tier = "economy" if (
     len(hypothesis.goals) == 1
     AND len([f for f in allowed_files if f != "VERSION"]) <= 5
     AND no /\b(rewrite|migrate|redesign|new endpoint|new component)\b/i match in any goals[]
   ) else "standard"
   ```
   `VERSION` is excluded from the count - it is a mandatory orchestrator-appended safety path, not a code-change scope indicator, so its presence must not inflate a 5-file economy run to standard (reflector 606d3abb). Reason string: `"len(goals)=N, allowed_files=M (VERSION-excluded), rewrite_match=<true|false>"` (mechanical; reproducible run-to-run). Write `{session}-tier.json`; producer-validate via `bash skills/apex/scripts/validate-json.sh tier.schema.json <path>`. Drives step 8 executor model + step 11 learn skip. Same prompt + scope -> same tier, every run.

## Mid-flow abort cleanup

Any orchestrator exit bypassing step 14 runs `bash skills/apex/scripts/session-end-hook.sh {session}` inline. Triggers:
- AskUserQuestion-abort at step 1 (no manifest yet -> skip session-end-hook)
- AskUserQuestion-abort at step 2 active-detected (no manifest written -> skip)
- Step 6 cascade-empty + abort
- Step 6 cascade-empty + proceed-with-prompt-paths but zero validated paths
- Step 8 conflict-check abort
- Step 10 verify cap-3 + `abort`
- Any unexpected error path

Claude Code SessionEnd hook catches the case where the entire CC session ends mid-/apex; the inline call covers "user aborts /apex but stays in the same CC session" so the manifest does not orphan and trigger false-positive concurrency from sibling /apex calls.

See `apex-core.md` for the full per-step contract (artifacts, exit codes, schemas, abort paths) and Conventions block (safety paths, cc_session_id resolution, manifest schema, scope-check hook, file-health hook, trace path schema, JSON-Schema validation).
