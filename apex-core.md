# /apex

Apex is the main orchestrator in the main session.

For a summary of steps, skill / agent / script used, and routing conditions, see `apex-core-overview.md`.

## Tiers (cross-cutting)

- **trivial** decided at step 3 (conservative pre-flight; ANY ambiguity = non-trivial). Step 3.1 inline single Edit/Write -> jump to step 14. Skips 4-13.
- **economy** decided at step 7 by deterministic rule. Step 8 executors run on Sonnet; **step 9 polish skipped**; step 11 skips `learn`.
- **standard** default at step 7 when the deterministic rule does not classify economy. Step 8 executors run on the main session model; full tail.

**Step 13 reflector is background** in non-trivial paths (economy + standard); the reflector owns the post-reflect `cleanup-session.sh` call as its final action. Step 14 only runs on the trivial path (where step 13 was skipped). Step 15's inline summary is fully deterministic (no LLM hop, no git audit pass).

## Conventions

- **Standard safety paths** (always allowed in any scope artifact): `.claude-tmp/`, `~/.claude/tmp/`, `/tmp/{session}-*`, project `docs/**`, any `README*` file at any depth, and any `VERSION` file at any depth (basename match; bumped by the project-side deploy skill batched across merged sessions, and by orchestrator post-agent inline bumps in non-/apex contexts - reflector 00bac875 surfaced the gate denial). The set is closed. `.env*` and `.git/` are NEVER safety paths regardless of scope contents. **Cross-worktree exclusion**: paths matching `*/.apex-worktrees/<X>/.claude-tmp/*` are explicitly NOT safety paths - they reach into a sibling worktree's apex-active and must go through the normal `allowed_files` check (a subagent's own worktree-relative `.claude-tmp/...` writes still pass-through unchanged; only cross-worktree resolutions are gated).
- **Project context** (architecture entry point): `<project-root>/docs/project-context.md`. Read at step 1 (best-effort; absent = silent skip; cap read at ~200 lines). Cached for downstream steps via working memory; consumers re-read directly when their work requires it.
- **Project lessons paths**: `<project-root>/.claude/lessons-index.md` (curated index; consumed by step 5 `grep-lessons.sh`), `<project-root>/.claude/lessons.md` (curated body), `<project-root>/.claude/lessons-archive.md` (older / superseded). `learn.md` (step 11) appends novel patterns to `<main-worktree>/.claude-tmp/lessons-tmp.md` (MAIN-anchored via `git rev-parse --git-common-dir`, not the apex-session worktree which `cleanup-session.sh` tears down on completion). `/apex-lessons` extract reads from the same MAIN-anchored path. Curation is out of scope for /apex.
- **Project CLAUDE.md budget**: `<project-root>/CLAUDE.md` loads on every turn; Claude Code degrades past a ~40k-char hard cliff (the warning the user sees). Apex soft ceiling = 30k chars. Every apex writer of project CLAUDE.md enforces this: `apex-init/create.md` seeds well under it, `apex-lessons/route.md` gates each Project-CLAUDE.md route on it (route to `docs/` instead on breach; evict superseded section bodies to `docs/` leaving a one-line pointer until back under 30k), and `agents/documentation.md` relocates detail to `docs/` rather than growing it. Leanness over completeness - CLAUDE.md holds broadly-applicable rules and pointers, never accumulated detail. Global `~/.claude/CLAUDE.md` is user-curated and exempt from auto-eviction.
- **Worktree dependency bootstrap**: `git worktree add` only checks out tracked files, so gitignored caches (`node_modules` / `.venv` / `venv` / `target` / `.gradle` / `.next` / `.nuxt` / `.turbo`) and `.env*` files are absent in the freshly-minted worktree. Three layers cover the gap (cheapest first; reflector 4cbf7e86: worktree without `node_modules` caused step-10 to fail until manual `pnpm install`). Layer 1 (default in `create-session.sh`): symlink each cache dir + `.env*` file from the main worktree into the new worktree when present in main. Zero cost, transparent; covers fresh-clone-then-apex and any project that installed once in main. The `.env` symlink is the documented exception to the "never read .env" safety rule - symlinking via `ln -s` is not reading. Layer 2 (optional, project-supplied): `create-session.sh` runs `docs/apex-bootstrap.sh` (preferred) or `.apex/bootstrap.sh` from the worktree root post-symlink if present, for projects that need codegen / install / DB seed beyond the symlink. Non-zero exit is non-fatal (continues to manifest write). Layer 3 (defensive in `verify-build.sh`): when `node_modules` is still absent at step-10 entry (Layer 1 found nothing to symlink, Layer 2 absent or skipped), run the PM's `--frozen-lockfile` install once before lint/build instead of feeding "module not found" to the executor fix-loop. Same fallback hierarchy applies to other languages by extension (`.venv` / `target` / etc.) once their verify-build branches add it.
- **Session token format**: 8-char lowercase hex (short guid generated at step 2 via `openssl rand -hex 4`).
- **cc_session_id resolution**: Claude Code does NOT export the active session id as a bash env var. Every apex script that needs `cc_session_id` resolves through `scripts/get-cc-session-id.sh` (env-var fast path then most-recent-jsonl fallback at `~/.claude/projects/<encoded-cwd>/`, where `<encoded-cwd> = pwd | tr '/.' '--'`). Step 2 invokes `create-session.sh --cc-session-id "$(bash scripts/get-cc-session-id.sh)"`.
- **JSON Schema validation helpers**: `scripts/_validate.py` (python module - `producer_validate(data, schema_name)` raises `ValidationError`; `consumer_load(path, schema_name)` returns `None` on missing/invalid; schema dir resolved via `APEX_SCHEMA_DIR` env var if set, otherwise defaults to `skills/apex/schemas/` relative to the module) and `scripts/validate-json.sh <schema-name> <json-path>`. Producer scripts validate before write; orchestrator inline-LLM producers (steps 4, 7) validate immediately after `Write`. Apex hot path falls back to JSON-parse-only when `jsonschema` is not importable (one-line stderr warning).
- **Session manifest schema** (`<worktree>/.claude-tmp/apex-active/{session}.json`): `{session, pid, cc_session_id, worktree_path, branch, base_branch}` (all required). `pid` is the OS process id of the live claude main process - resolved by `scripts/find-claude-pid.sh` (walks up the process tree from the script's `$$` until a process with `comm` basename `claude` is found). `cc_session_id` is the Claude Code session id captured at step 2. `worktree_path` is the absolute path to `<main-worktree>/.apex-worktrees/<session>/`. `branch` is the `apex/<session>` ref the worktree owns. `base_branch` is the branch HEAD was on at step 2 - what `/apex-merge` lands the session back onto. Optional `bump_hint: patch|minor` is populated by step 12 (the orchestrator persists the classified tier into the manifest); the project-side deploy skill picks the highest tier across the batch when bumping VERSION (`/apex-merge` no longer owns the bump). Worktree isolation removes the sibling-commits-during-our-run scenario, so the `base_branch` field alone anchors every diff downstream: agents derive a `diff_anchor` as `git merge-base $base_branch HEAD` (the apex/<session> fork point), stable from session mint through step 15. No producer step writes a snapshot file - the manifest is the single source of truth.
- **Scope write producers** (single source of truth for `{session}-main-scope.json`, exactly one fires per session): trivial path -> orchestrator inline `Write` at step 3.1; non-trivial path -> `agents/discoverer.md` at step 6.
- **Scope-check pointer**: written immediately after each scope write at `.claude-tmp/apex-active/{session}-scopes/{cc_session_id}.txt` (single-line absolute path to the scope JSON). The PreToolUse hook reads this pointer to gate `Edit` / `Write` / `MultiEdit` / `NotebookEdit`.
- **Trace path schema**: `.claude-tmp/apex-active/{session}-traces/{phase}/{agent}[-{disambiguator}].md` where `{phase}` is `entry` (steps 1-7), `execute` (step 8), `verify` (step 10), or `tail` (step 11). `{disambiguator}` is optional (task-id, attempt-N).
- **Side-effects log** (`.claude-tmp/apex-active/{session}-side-effects.jsonl`): per-line JSON `{"cmd","ts"}` recording each state-mutating Bash command the step-8 executor ran in this worktree (migrations, seeders, codegen producing untracked output, deps installs touching system state). Read-only commands (lint / typecheck / build / test) are excluded. Consumed by `/apex-merge` step 4.5 (`skills/apex-merge/scripts/replay-side-effects.sh`) which aggregates across all merged worktrees, dedupes by verbatim cmd, and surfaces the unique set via AskUserQuestion for replay on the main worktree post-merge. Absent log = no replay candidates for that session (clean text-only diff).
- **scope-check hook** (`skills/apex/scripts/scope-check-hook.sh`): PreToolUse on `Edit` / `Write` / `MultiEdit` / `NotebookEdit`. Bash file operations (`sed -i`, redirection, `cp`, `mv`, etc.) are NOT gated by the hook; subagent and skill prompts must restrict file modifications to the hook-gated tools (convention-enforced at the prompt layer). Resolves the active scope file via on-disk pointer (env-var indirection rejected: Claude Code's Bash tool runs each invocation in a fresh subshell). The hook extracts `session_id` from its stdin event JSON and globs `.claude-tmp/apex-active/*-scopes/{session_id}.txt` (any apex `{session}` matches; in practice exactly one matches the calling session_id). Pointer-miss is tri-state: (a) no active main-scope.json in this worktree's apex-active -> pass-through (entry-flow / non-/apex session); (b) active main-scope.json exists -> enforce it directly (per-worktree isolation guarantees at most one orchestrator per apex-active dir, so no PID disambiguation is needed - the single main-scope is the subagent's parent). Safety-path fast-path also rejects cross-worktree `.apex-worktrees/<X>/.claude-tmp/...` paths so a subagent in worktree A cannot slip a write into worktree B's apex-active via the generic `.claude-tmp/` rule - those go through the normal `allowed_files` check instead.
- **file-health hook** (`skills/apex/scripts/file-health-hook.sh`): PreToolUse safety net during step 8 execute. Blocks `Edit` / `Write` on files > 500 LOC; nudges to split first. Pre-flight wc-l queue at step 8 init handles the > 400 LOC cases ahead of edits to avoid hot-path stalls.
- **block-destructive hook / NEVER stash** (`skills/apex/scripts/block-destructive-hook.sh`): PreToolUse on `Bash`, uniform across the orchestrator and every subagent (executor, discoverer, screener, reviewer, etc.) - no per-agent contract drift possible. Apex agents must NEVER `git stash` work: per-session worktrees eliminate cross-session sibling overlap, but the orchestrator + co-resident subagents inside ONE worktree share a single working tree, and a bare `git stash` (= `git stash push`) from any of them silently captures EVERY co-resident agent's uncommitted edits into a single stash ref, which presents as catastrophic work loss for parallel siblings. The hook denies all stash-creation forms (bare / `push` / `save` / `create` / `store` / any flag form like `-p` `-u` `-m`); read-only (`list` / `show`) and non-destructive recovery (`apply` / `branch`) stay allowed, `pop` has its own deny. Agents needing a clean tree must commit, not stash.
- **audit-and-rescope (step 11)**: when a tail agent (`documentation.md` / `learn.md`) flags drift in adjacent, pattern-aligned files outside the planned scope, the orchestrator re-scopes the session (updates `{session}-main-scope.json` + scope-check pointer) and fixes inline in the same tail phase rather than spawning a new /apex run. Limited to same convention / file family (e.g., a docs file paired with the code module just touched); cross-domain drift escalates back to the user.
- **Parallel /apex on one project**: two Claude Code sessions running /apex against the same project repo mint independent worktrees at `<main>/.apex-worktrees/<sessionA>/` and `<main>/.apex-worktrees/<sessionB>/`, each with its own branch (`apex/<sessionA>`, `apex/<sessionB>`), index, working tree, and `.claude-tmp/apex-active/`. The two sessions never observe each other's edits during execution. Each lands back on its recorded `base_branch` via its own `/apex-merge` run; if the two scopes overlap textually, the second merge surfaces conflicts in the normal `/apex-merge` step 4 flow (resolver agent + AskUserQuestion). No special coordination is needed at session mint - worktree isolation is the coordination.
- **Spawn-prompt tone (Opus 4.7 / Sonnet 4.6)**: apex orchestrator + agent prompts target models that over-trigger on legacy anti-laziness over-prompting. State instructions in plain declarative phrasing; reserve emphatic `CRITICAL` / `you MUST` / `NEVER` for genuine safety / contract invariants (scope-check, destructive-op, fail-closed), not as routine reinforcement. Newer models follow instructions literally - explicit scope ("apply to every X, not just the first") beats volume. Tightening over-emphatic prose toward plain phrasing is an in-band `/apex-improve` semantic edit, never an additive rule.

1. Analyze + read project-context.md
   - inline task prompt
     - analyzes prompt
     - AskUserQuestion if ambiguous; abort = clean exit (no manifest yet)
     - reads `<project-root>/docs/project-context.md` if present (best-effort; absent = silent skip; cap read at ~200 lines)
     - **goals decomposition expectation**: when forming the working interpretation, expect step 4 to emit a `goals[]` array (1..N items). Single-task prompts ("fix the typo in login.tsx") -> one goal verbatim. Multi-task / audit prompts ("make sure all kie image-gen models have settings + costs wired") -> N enumerated goals, each a discrete actionable check. `goals.length` drives downstream behaviour at step 6 (top-K), step 7 (deterministic tier rule), step 8.2 (per-goal task split), step 13 (non-convergence detection), step 15 (per-goal summary). Internal bias only at step 1; no user-visible change.
     - **plan-completed early-exit (continue-file form)**: when `original_prompt` is a `continue: <plan-file>` form and every top-level goal in that plan file is already `[x]` / DONE, this is a structurally distinct prompt from a fresh goal - the prompt-hash collides with prior runs of the same plan and resolves to a different file set each time, which the step-13 non-convergence guard catches only post-hoc. Surface it as a named case here: AskUserQuestion (`close-plan-nothing-to-do` | `narrow-to-explicitly-deferred-items` | `re-spec`); dismiss = `close-plan-nothing-to-do` (clean exit, no manifest yet). When the plan carries a status section that may be stale, field-presence is NOT proof of completion - run the plan's own encoded acceptance tests as the satisfiability discriminator before declaring it complete (reflector cluster ff441791 / f5d3280a / 4c92e825 / b2716ff4 / 35b42f2b: continue-form prompt-hash collided across 5 sessions touching 0/9/12/53/14 files; 2c226d56: a stale status section needed acceptance-test proof, not field-presence).

2. Create session manifest | Blocked by #1
   - script `scripts/create-session.sh --cc-session-id "$(bash scripts/get-cc-session-id.sh)"`
     - exit 0: `{session}` token to stdout; manifest written + producer-validated against `manifest.schema.json`.
     - exit 1: unrecoverable error (bad args, openssl missing, nested-worktree, detached HEAD, non-git repo). Surface stderr; no manifest written so `session-end-hook.sh` is skipped; exit cleanly.
     - **Worktree creation (unconditional)**: `create-session.sh` captures `base_branch = git symbolic-ref --short HEAD`, creates the worktree at `<main-worktree>/.apex-worktrees/<session>/` on branch `apex/<session>` off HEAD, `cd`s into it, and persists `{worktree_path, branch, base_branch}` in the manifest (per `manifest.schema.json`). All subsequent /apex steps execute inside the worktree (isolated `.claude-tmp/apex-active/`, isolated index, isolated working tree). Per-worktree isolation removes the sibling-session conflict surface entirely - no concurrent-apex overlap detection / scope-overlap classification is needed at session mint. Nested-worktree guard refuses to start from a secondary worktree; detached-HEAD / non-git-repo guards refuse to mint without a base branch. `cleanup-session.sh` reads `worktree_path` and forks (clean+no-commits-past-base = `git worktree remove --force` + `git branch -D`; clean+commits = keep, warn awaiting `/apex-merge`; dirty = keep, warn). `session-end-hook.sh` scans `<main>/.apex-worktrees/*/.claude-tmp/apex-active/*.json` to locate the worktree-resident manifest and forwards `--apex-active-dir` to cleanup. Integration is the `/apex-merge` skill (`skills/apex-merge/SKILL.md`; spawns `agents/apex-merge-resolver.md` per conflicted file when a merge surfaces conflicts; manual trigger from the main worktree).

3. Trivial pre-flight | Blocked by #2
   - inline task prompt
     - **Trivial = ALL of**: single file edit (or single new file), file path explicitly named in `original_prompt`, no new public symbol / endpoint / component, no cross-file dependency. **ANY ambiguity = non-trivial.**
     - **Verb-pattern relaxation**: when `original_prompt` matches `/^\s*(rename|format|fix typos?|reword|add (a )?comment|remove (a )?comment|update copy|update string)\b/i`, the path-naming requirement is relaxed: if no path is named, a single inline `Glob` for the most specific noun in the prompt qualifies the prompt iff exactly one match returns (zero or 2+ matches = non-trivial). All other trivial constraints (no new public symbol, no cross-file dep, ANY ambiguity disqualifies) still apply. Pure edit-only prompts ("rename `foo` to `bar`", "fix typo in landing copy") thus reach step 3.1 and skip 4-13.
   - if trivial:
     - **3.1** orchestrator performs the inline `Edit` / `Write` directly. Before the edit, orchestrator writes `{session}-main-scope.json` inline (`allowed_files = [<the single file>] + safety paths`) and writes the scope-check pointer. Orchestrator also writes a **minimal hypothesis stub** at `.claude-tmp/apex-active/{session}-hypothesis.json` (`original_prompt` verbatim; `hypothesis` = one-line restatement; `complexity_hint = "low"`; `alternatives = [{interpretation: original_prompt, status: "kept", reason: "trivial path"}]`; producer-validates against `hypothesis.schema.json`) so step 15's summary contract stays uniform across trivial / non-trivial. After the edit, jumps to task 14.
     - **trivial trade-off**: skips verify (10), commit (12), reflect (13). The conservative gate (single named file, no new public symbol, no cross-file dep, ANY ambiguity disqualifies) keeps the edit reversible and small; the user owns lint/build verification and the `git add+commit` afterwards. Misclassification is on the gate, not the trivial path.
     - tasks 4 - 13 marked completed-skipped so TaskList reflects reality.

4. Hypothesis | Blocked by #3
   - inline task prompt
     - emits `original_prompt` (verbatim user prompt - preserves wording for downstream reflector and step 15 summary; do NOT paraphrase)
     - emits `hypothesis` (1 - 2 sentence working interpretation; not a plan, not a task list)
     - emits `complexity_hint: low|medium|high` (advisory; consumed by step 7 economy classifier as one signal)
     - emits `alternatives: [{interpretation, status: kept|rejected, reason}]` - 1 - 3 narrower / broader scope readings, each a structured anti-bias check. minItems: 1 schema-required.
     - emits `goals: [string]` - 1..N items, each a discrete actionable check or task. Free-text 1-3 sentences each. Single-task prompts: one goal (the prompt verbatim, lightly normalized). Multi-task / audit prompts: enumerate one goal per discrete check ("verify each model has cost wired", "verify backend node wiring", ...). Same prompt -> same goals[] (deterministic from prompt + step 1's bias hint), which is what makes the per-goal split at step 8.2 idempotent across re-runs. Schema: `goals` is an additive optional array (old hypothesis JSONs without it still validate); the new flow always populates it with at least one item.
     - emits `discovered_paths: [<paths>]` (optional) - when `original_prompt` has no path tokens AND `complexity_hint != "low"`, spawn a small Explore subagent (`Agent(subagent_type: "Explore")`) to gather candidate repo-relative paths; the subagent returns ONLY paths that exist on disk. Empty / absent when the prompt itself names paths, when complexity is low, or when the prompt is too abstract for the Explore subagent to anchor.
     - writes `.claude-tmp/apex-active/{session}-hypothesis.json`; producer-validates via `bash scripts/validate-json.sh hypothesis.schema.json <path>`. On validation failure: abort with explicit error.

## Failure handling

- `cleanup-session.sh` is idempotent: exit 0 on partial cleanup with warnings to stderr. Worktree-only - reads the manifest's `worktree_path` / `branch` / `base_branch` and forks on worktree state (clean+no-commits-past-base = `git worktree remove --force` + `git branch -D`; clean+commits = keep, warn awaiting `/apex-merge`; dirty = keep, warn). The worktree sweep removes manifest + scope + traces + tier + screened + hypothesis + every other `{session}-*` artifact atomically because they all live inside the worktree subtree. **APEX_ACTIVE resolution** (priority chain, first non-empty wins): `--apex-active-dir <abs>` flag > `APEX_ACTIVE_DIR` env > `$CLAUDE_PROJECT_DIR/.claude-tmp/apex-active` > `$PWD/.claude-tmp/apex-active`. Background reflector subagents (apex step 13) may not inherit project CWD; pass `--apex-active-dir` explicitly from the spawn prompt. **Stdout / cd-back contract** (user-driven 35679220): on every branch where `worktree_path` resolves, the script prints the absolute main-worktree path on the last stdout line. Mid-/apex abort callers MUST capture this and `cd` there so the orchestrator shell leaves the (possibly removed) worktree subdirectory. Normal-flow cd-back is owned by step 15.0 below; the prior step-13 / step-14 mid-paragraph one-liners drifted across long-context runs and were collapsed into 15.0. **Step 15.0 cd-back sweep** (user-driven f1d8b458): step 15 (inline summary; always runs on every non-aborted path) opens with an idempotent `dirname(dirname(WORKTREE_PATH))` cd-back BEFORE any reads / emits - sole canonical post-/apex cd-back guard.
