# /apex

Apex is the main coding orchestrator in the main session - fenced-dynamic: the orchestrator sequences the work itself, like a senior engineer, inside deterministic rails. There is no fixed step sequence and no read-gate. The runtime contract lives in `skills/apex/SKILL.md`; the execution summary lives in `apex-core-overview.md`; this file holds the architecture rationale plus the cross-cutting conventions the rest of the framework cites.

## Model

Three things distinguish /apex from native dynamic work:

- **Model routing.** One lane decision per session (`trivial` / `standard` / `complex`, picked once at session start): trivial edits inline; standard and complex delegate to `agents/executor.md` on Sonnet, with Opus reserved for a single slice that genuinely needs reasoning - never a lane default.
- **Bounded-context delegation (think / do split).** The orchestrator reasons, plans, routes, and verifies at low token volume; bounded executor subagents do the high-volume reading and writing. Executors get the smallest single-purpose tasks with named target files and a minimal-diff demand; `partial` returns are redispatched smaller, never re-run broader.
- **Deterministic guardrails.** A per-session git worktree fence bounds every edit; file-health, protect-env, and block-destructive hooks fire regardless of the orchestrator's choices. The verify gate (targeted checks or `verify-build.sh`) is contract-level, not hook-enforced: the orchestrator must obtain a clean verifying exit before any "done" claim, and nothing downstream re-checks it.

The worktree IS the scope. There is no file-level allow-list, no discovery-computed scope, and no scope pointer - blast radius is one throwaway branch, and integration back onto the base branch is `/apex-merge`'s job.

## Session lifecycle

1. **Mint**: `skills/apex/scripts/mint-worktree.sh` (run from the project root, main worktree only) mints `{session}` (8-hex), creates `<main>/.apex-worktrees/<session>/` on branch `apex/<session>` off HEAD, symlinks gitignored dep caches + `.env*` from main, runs an optional project bootstrap hook, and writes a minimal manifest. Non-git cwd, `~/.claude` cwd, secondary worktree, or detached HEAD refuse to mint (exit 1).
2. **Work**: the orchestrator `cd`s into the worktree (this cwd-arms the fence; the mint-time session record backstops unanchored contexts) and drives understand / implement / verify / polish / docs / commit in whatever order the task needs. Each independently-verified slice gets its own commit on `apex/<session>`.
3. **Hand off**: `/apex-merge` folds `apex/<session>` back onto its recorded `base_branch` and removes the worktree. `/apex` never merges, pushes, or tears down its own worktree.

## Conventions

- **Worktree fence** (`skills/apex/scripts/worktree-fence-hook.sh`, PreToolUse on `Edit` / `Write` / `MultiEdit` / `NotebookEdit`): two arming modes. **cwd-armed** - the session cwd (hook process `$PWD` first, the event JSON's `cwd` as fallback) is inside `.apex-worktrees/<token>/`; relative targets resolve under the cwd and pass; absolute targets must sit under the worktree root. **record-armed** - the cwd is outside any worktree but the CC session minted one: `mint-worktree.sh` records the worktree root under `$APEX_FENCE_DIR/` (default `~/.claude/tmp/apex-fence/`) keyed BOTH by cc_session_id and by `pid-<claude-pid>` (the pid key survives `/clear` session-id rotation and is shared with in-process subagents), so an unanchored subagent's (or post-teardown replay's) writes are still fenced, with relative targets resolved under the event cwd and classified like absolute ones. Both modes: framework scratch (`~/.claude/tmp/`, `/tmp/`, `/private/tmp/`, `/var/folders/` - the harness scratchpad lives under `/private/tmp` on macOS) stays writable; everything else (main tree, `~/.claude` sources, sibling worktrees) is denied. Neither armed -> fail-open (non-apex sessions unaffected). A record whose worktree is gone is stale - dropped on read, and disarmed eagerly by `/apex-merge` precheck and the apex SessionEnd hook, so post-integration main-tree work is never blocked; the record-armed deny message carries the `rm <record>` disarm for intentional main-tree writes. Bash file writes are tripwire-gated by `block-destructive-hook.sh` (same arming model, below); agent contracts still restrict file mutation to the gated tools. Subagents do NOT inherit the orchestrator's cwd: every executor brief passes the absolute `worktree_path` and requires `cd` + `pwd` confirmation first - the record fence backstops a brief that skips the anchor, it does not license skipping it.
- **Safety / scratch paths**: `.claude-tmp/` (worktree- or repo-resident artifacts), `~/.claude/tmp/` (framework logs + signals), and `/tmp/` (+ its macOS physical forms `/private/tmp/` and `/var/folders/`) are the always-writable scratch surfaces. The set is closed. `.env*` and `.git/` are NEVER writable regardless of location - `protect-env-hook.sh` (PreToolUse `Read`/`Edit`/`Write`) and `block-destructive-hook.sh` (PreToolUse `Bash`) enforce this for every agent uniformly. `/admin-apex` follows the same rules on its own `.claude-tmp/admin-apex-active/` tree.
- **Session token format**: 8-char lowercase hex (`openssl rand -hex 4`), minted by `mint-worktree.sh` and echoed on stdout - thread the EXACT stdout token, never fabricate one.
- **Session manifest** (`<worktree>/.claude-tmp/apex-active/{session}.json`): minimal by design - `{session, branch, base_branch, worktree_path}`, written by `mint-worktree.sh`, no schema validation. `/apex-merge` reads `base_branch` (jq, default main) and derives the worktree from `git worktree list`. Deliberately absent: `pid` and `cc_session_id` (a pid-less manifest's liveness is unknowable, so the SessionEnd reaper age-gates it - manifest older than `APEX_REAP_AGE_HOURS`, default 24 - before applying the worktree-state decision below; committed or dirty worktrees are always preserved for `/apex-merge`, and the age gate keeps a live session's clean just-minted worktree safe from sibling SessionEnds).
- **Side-effects log** (`<worktree>/.claude-tmp/apex-active/{session}-side-effects.jsonl`): per-line JSON `{"cmd","ts"}` recording each state-mutating Bash command an executor ran in the worktree (migrations, seeders, codegen producing untracked output, dep installs). Read-only commands (lint / typecheck / build / test) are excluded. Consumed by `/apex-merge` step 4.5 (`skills/apex-merge/scripts/replay-side-effects.sh`), which aggregates across merged worktrees, dedupes by verbatim cmd, and surfaces the unique set via AskUserQuestion for replay on main. Absent log = no replay candidates.
- **Worktree dependency bootstrap**: `git worktree add` only checks out tracked files, so gitignored caches (`node_modules` / `.venv` / `venv` / `target` / `.gradle` / `.next` / `.nuxt` / `.turbo`) and `.env*` are absent in a fresh worktree. Three layers cover the gap, cheapest first. Layer 1 (default in `mint-worktree.sh`): symlink each cache dir + `.env*` file from the main worktree when present (monorepo subpackage `node_modules`/`dist` included). The `.env` symlink is the documented exception to the never-read-.env rule - `ln -s` is not reading. Layer 2 (optional, project-supplied): `mint-worktree.sh` runs `docs/apex-bootstrap.sh` (preferred) or `.apex/bootstrap.sh` post-symlink when present; non-zero exit is non-fatal. Layer 3 (defensive in `verify-build.sh`): when `node_modules` is still absent at verify time, run the package manager's frozen-lockfile install once before lint/build instead of feeding "module not found" to the fix-loop.
- **file-health hook** (`skills/apex/scripts/file-health-hook.sh`): PreToolUse safety net on `Edit` / `Write` / `MultiEdit`. Blocks when the existing file is > 400 LOC AND the change adds > 10 net lines; trivial edits pass even on > 500-LOC files. Per-path word budgets for framework docs resolve via `skills/apex/scripts/content-budget.json`. Splitting a capped file is a deliberate orchestrator-dispatched task, never an executor side-effect.
- **block-destructive hook / NEVER stash** (`skills/apex/scripts/block-destructive-hook.sh`): PreToolUse on `Bash`, uniform across the orchestrator and every subagent. Apex agents must NEVER `git stash`: the orchestrator + co-resident subagents inside ONE worktree share a single working tree, and a bare `git stash` silently captures every co-resident agent's uncommitted edits into one stash ref. The hook denies all stash-creation forms plus `pop` / `apply` / `branch`; only read-only `list` / `show` pass. Agents needing a clean tree must commit, not stash. Coverage beyond stash: git prefix options (`-c` / `-C`) are consumed before subcommand matching; `checkout`-with-pathspec / `restore` / `reset --hard|--keep|--merge` / `clean -f` / any force push (flag or `+refspec`) / history-extraction redirects deny; recursive `rm` denies on root/home/dot targets, `.apex-worktrees`, and absolute paths outside tmp scratch; shell readers/copiers of `.env*` deny; `git worktree remove` and `git branch -D` deny when the cwd is inside an apex worktree (self-teardown belongs to `/apex-merge` or the user, from MAIN). Fence tripwire (armed apex sessions only; same cwd-or-record arming as the worktree fence): Bash write targets - redirects, `tee`, `sed -i`, `cp` / `mv` destinations - resolving outside the worktree deny (framework scratch and MAIN `.claude-tmp/`, the lessons side-channel, allow-listed), and benign-form git tree mutations (`add` / `commit` / `checkout` / ...) whose effective tree (`-C` / `--work-tree` path, else the cwd) sits outside the worktree deny - closing the `git -C <main> add + commit` and unanchored plain-`git commit` leaks. It is a tripwire against accidental forms, not a boundary - script indirection can evade string matching; the fence and agent contracts carry the rest.
- **Project-side `.claude-tmp` anchoring**: skills that run in the MAIN tree and write `.claude-tmp/` artifacts via CWD-relative paths (`apex-fix`, `apex-lessons`) MUST first anchor to the repo root (`cd "$(git rev-parse --show-toplevel 2>/dev/null || pwd)"`), so launching from a monorepo subdir does not create a stray `apps/web/.claude-tmp/`. `/apex` is exempt - `mint-worktree.sh` hard-refuses a non-toplevel cwd and the session then operates worktree-isolated. `/apex-improve` and `/admin-apex` anchor to `~/.claude`.
- **cc_session_id resolution**: Claude Code does not export the active session id as an env var. Every framework script that needs it resolves through `skills/apex/scripts/get-cc-session-id.sh` (env-var fast path; then ancestor PID-walk parsing `claude ... --session-id <UUID>`; then most-recent-jsonl fallback at `~/.claude/projects/<encoded-cwd>/`). Used by the admin-side skills (`/admin-apex`, `/apex-improve`, `/apex-merge`, `/apex-lessons`) to arm their SessionEnd sweeps - apex session manifests deliberately omit it.
- **JSON Schema validation helpers**: `skills/apex/scripts/_validate.py` (`producer_validate(data, schema_name)` raises; `consumer_load(path, schema_name)` returns `None` on missing/invalid; schema dir via `APEX_SCHEMA_DIR`, no default schema set ships with /apex itself) and `skills/apex/scripts/validate-json.sh [--admin] <schema-name> <json-path>`. The apex hot path produces no schema-validated artifacts; the helpers serve the admin-side skills (`/admin-apex`, `/apex-improve`), whose schemas live at `skills/admin-apex/schemas/`.
- **Project context**: `<project-root>/docs/project-context.md` is the architecture entry point (seeded by `/apex-init`). Read it best-effort during understand; absent = silent skip.
- **Project lessons paths**: `<project-root>/.claude/lessons-index.md` (curated index; `skills/apex/scripts/grep-lessons.sh` pulls from it), `.claude/lessons.md` (curated body), `.claude/lessons-archive.md` (older / superseded). Session lessons append to `<main-worktree>/.claude-tmp/lessons-tmp.md` (MAIN-anchored via `git rev-parse --git-common-dir`, not the session worktree that `/apex-merge` tears down); `/apex-lessons` curates from there. Appends go through `skills/apex/scripts/append-with-lock.sh` (never raw `flock` - macOS lacks the binary).
- **Lessons routing taxonomy (4 stores)**: `/apex-lessons` analyze routes each confirmed lesson to one of four homes - `lessons.md` (rare/narrow runtime lookups, grep-pulled), `.claude/rules/*` (`[verified]` path-scoped terse gotchas, auto-pushed on path touch), `docs/` (reference/contracts, pointer-pulled), and project/global `CLAUDE.md` (always-on broad rules + pointers). See `skills/apex-lessons/route.md`.
- **Project CLAUDE.md budget**: `<project-root>/CLAUDE.md` loads on every turn; Claude Code degrades past a ~40k-char hard cliff. Apex soft ceiling = 30k chars, enforced by every apex writer of project CLAUDE.md (`apex-init` seeds under it; `apex-lessons/route.md` gates routes on it and evicts superseded bodies to `docs/`). Leanness over completeness. Global `~/.claude/CLAUDE.md` is user-curated and exempt.
- **Parallel /apex on one project**: two Claude Code sessions mint independent worktrees on independent branches, each with its own index, working tree, and `.claude-tmp/apex-active/`. They never observe each other's edits; each lands back via its own `/apex-merge` run, where textual overlap surfaces as ordinary merge conflicts. Worktree isolation IS the coordination.
- **Spawn-prompt tone**: state instructions in plain declarative phrasing; reserve emphatic `CRITICAL` / `MUST` / `NEVER` for genuine safety / contract invariants (fence anchoring, destructive-op, fail-closed), not routine reinforcement. Explicit scope ("apply to every X, not just the first") beats volume.
- **Lean prose (no negative-scope, no incident-narrative)**: document what a component does now plus where related work lives. Do NOT add `What X does NOT do` / `Out of scope` disclaimer sections or scope-negative bullets - an unstated non-responsibility is not a gap. Do NOT justify a rule by recounting the incident that motivated it; state the rule positively and cite a cluster slug or nothing - git history holds the why. Operational negatives that govern current behavior (`never blind-edit`, hard caps) are rules, not disclaimers - keep them. Enforced deterministically at audit + polish by the `hash-roster` and `negative-scope` detectors in `skills/admin-apex/scripts/audit-detectors.py`.
- **Tool-output integrity (never act on unread output)**: every factual claim an apex agent makes - file content, exit code, line count, push / commit result - must trace to a tool result actually read THIS turn. When one turn fires multiple tool calls, bind each claim to the specific call whose result was read, never by position; re-run an interleaved or ambiguously-owned check in isolation before asserting off it. Unreadable output (garbled, doubled, empty, unparseable) is a HARD STOP: re-run once, else redirect to a file and `Read` it, else halt and surface. Gate every destructive / outward-facing step (commit, push, `rm`, `git restore`) on a CLEAN precondition read. Report a non-zero exit / failed push as a failure with its evidence - never smooth it into "done".
- **`/apex-fix` verify scope**: `/apex-fix` invokes `verify-build.sh` WITHOUT `--with-tests` (whole-repo lint/build fix loop, no session worktree). `/apex` defaults to targeted per-package checks and escalates to `verify-build.sh --session {session} --with-tests` for cross-cutting changes.

## Failure handling

- `cleanup-session.sh` is idempotent: exit 0 on partial cleanup with warnings to stderr. Worktree-only - reads the manifest's `worktree_path` / `branch` / `base_branch` and forks on worktree state (clean + no commits past base = `git worktree remove --force` + `git branch -D`; clean + commits = keep, warn awaiting `/apex-merge`; dirty = keep, warn). The worktree sweep removes the manifest + every `{session}-*` artifact atomically because they live inside the worktree subtree. APEX_ACTIVE resolution (first non-empty wins): `--apex-active-dir <abs>` flag > `APEX_ACTIVE_DIR` env > `$CLAUDE_PROJECT_DIR/.claude-tmp/apex-active` > `$PWD/.claude-tmp/apex-active`.
- `session-end-hook.sh` wraps `cleanup-session.sh`. SessionEnd mode reads the stdin event's `session_id`, scans `<main>/.apex-worktrees/*/.claude-tmp/apex-active/*.json` for a matching `cc_session_id`, and forwards the located apex-active dir to `cleanup-session.sh`. It then sweeps sibling `.apex-worktrees/<token>/` dirs: manifest-less crash-orphans are removed inline, and manifest-present dirs whose owning session is not live (recorded `pid` dead or recycled; pid-less /apex manifests qualify only past the `APEX_REAP_AGE_HOURS` age gate, default 24h) get the `cleanup-session.sh` keep/remove decision re-run; unmerged / dirty worktrees are always preserved. It finishes with `sweep-orphan-artifacts.sh` against the MAIN worktree's apex-active (age-gated, manifest-absent-only) as defense-in-depth. Manual mode takes a positional session token and forwards `cleanup-session.sh` stdout (the main-worktree cd-back path) verbatim.
- `sweep-orphan-artifacts.sh` plugs the `{token}-*`-without-`{token}.json` leak: crash-orphaned sibling artifacts are removed once mtime exceeds `--age-hours` (default 24). `{run}-deferred-findings.json` is exempt (the apex-improve / admin-apex backlog is session-spanning). Best-effort; never blocks.
- A runaway or wedged session is abandoned, not fought: committed slices on `apex/<session>` are safe, the uncommitted mess is disposable, and the worktree is torn down by `/apex-merge` or the SessionEnd reaper - never by the session itself (see `skills/apex/SKILL.md` Rails).
