# /apex

Apex is the main orchestrator in the main session.

For a summary of steps, skill / agent / script used, and routing conditions, see `apex-core-overview.md`.

## Tiers (cross-cutting)

- **trivial** decided at step 3 (conservative pre-flight; ANY ambiguity = non-trivial). Step 3.1 inline single Edit/Write + lightweight commit -> jump to step 14. Skips 4-13.
- **economy** decided at step 7 by deterministic rule. Step 8 executors run on Sonnet; **step 9 polish skipped**; **step 10.5 review skipped**; step 11 skips `learn`.
- **standard** default at step 7 when the deterministic rule does not classify economy. Step 8 executors run on Opus; full tail.

**Step 13 reflector is background** in non-trivial paths (economy + standard); the reflector owns the post-reflect `cleanup-session.sh` call as its final action. Step 14 only runs on the trivial path (where step 13 was skipped). Step 15's inline summary is fully deterministic (no LLM hop, no git audit pass).

## Conventions

- **Standard safety paths** (always allowed in any scope artifact): `.claude-tmp/`, `~/.claude/tmp/`, `/tmp/{session}-*`, project `docs/**`, any `README*` file at any depth, and any `VERSION` file at any depth (basename match; bumped by the project-side deploy skill batched across merged sessions, and by orchestrator post-agent inline bumps in non-/apex contexts). The set is closed. `.env*` and `.git/` are NEVER safety paths regardless of scope contents. **Cross-worktree exclusion**: paths matching `*/.apex-worktrees/<X>/.claude-tmp/*` are explicitly NOT safety paths - they reach into a sibling worktree's apex-active and must go through the normal `allowed_files` check (a subagent's own worktree-relative `.claude-tmp/...` writes still pass-through unchanged; only cross-worktree resolutions are gated).
- **Project-side `.claude-tmp` anchoring**: skills that run in the MAIN tree (NOT an isolated `/apex` worktree) and write `.claude-tmp/` artifacts via CWD-relative paths - `apex-fix`, `apex-lessons` - MUST first anchor to the repo root (`cd "$(git rev-parse --show-toplevel 2>/dev/null || pwd)"`, mirroring `verify-build.sh`'s `PROJECT_ROOT` resolution and `create-session.sh`'s refuse-non-toplevel guard). Without the anchor, launching the skill from a monorepo subdir (e.g. `apps/web`) creates a stray `apps/web/.claude-tmp/` instead of resolving to the project-root `.claude-tmp/`. `/apex` itself is exempt - `create-session.sh` already hard-refuses a non-toplevel CWD and the session then operates worktree-isolated. `/apex-improve` and `/admin-apex` anchor to `~/.claude` (they operate on the framework, not the project).
- **Project context** (architecture entry point): `<project-root>/docs/project-context.md`. Read at step 1 (best-effort; absent = silent skip; cap read at ~200 lines). Cached for downstream steps via working memory; consumers re-read directly when their work requires it.
- **Project lessons paths**: `<project-root>/.claude/lessons-index.md` (curated index; consumed by step 5 `grep-lessons.sh`), `<project-root>/.claude/lessons.md` (curated body), `<project-root>/.claude/lessons-archive.md` (older / superseded). `learn.md` (step 11) appends novel patterns to `<main-worktree>/.claude-tmp/lessons-tmp.md` (MAIN-anchored via `git rev-parse --git-common-dir`, not the apex-session worktree which `cleanup-session.sh` tears down on completion). `/apex-lessons` extract reads from the same MAIN-anchored path. Curation is out of scope for /apex.
- **Lessons routing taxonomy (4 stores)**: `/apex-lessons` analyze routes each confirmed lesson to one of four homes - `lessons.md` (rare/narrow runtime lookups, grep-pulled), `.claude/rules/*` (`[verified]` path-scoped terse gotchas, auto-pushed on path touch via each rule's `paths:` glob), `docs/` (reference/contracts, pointer-pulled), and project/global `CLAUDE.md` (always-on broad rules + pointers). `[verified]` is a graduation signal that qualifies the rules branch, not a terminal keep. See `skills/apex-lessons/route.md` Step 6.
- **Project CLAUDE.md budget**: `<project-root>/CLAUDE.md` loads on every turn; Claude Code degrades past a ~40k-char hard cliff (the warning the user sees). Apex soft ceiling = 30k chars. Every apex writer of project CLAUDE.md enforces this: `apex-init/create.md` seeds well under it, `apex-lessons/route.md` gates each Project-CLAUDE.md route on it (route to `docs/` instead on breach; evict superseded section bodies to `docs/` leaving a one-line pointer until back under 30k), and `agents/documentation.md` relocates detail to `docs/` rather than growing it. Leanness over completeness - CLAUDE.md holds broadly-applicable rules and pointers, never accumulated detail. Global `~/.claude/CLAUDE.md` is user-curated and exempt from auto-eviction.
- **Worktree dependency bootstrap**: `git worktree add` only checks out tracked files, so gitignored caches (`node_modules` / `.venv` / `venv` / `target` / `.gradle` / `.next` / `.nuxt` / `.turbo`) and `.env*` files are absent in the freshly-minted worktree. Three layers cover the gap (cheapest first; worktree without `node_modules` caused step-10 to fail until manual `pnpm install`). Layer 1 (default in `create-session.sh`): symlink each cache dir + `.env*` file from the main worktree into the new worktree when present in main. Zero cost, transparent; covers fresh-clone-then-apex and any project that installed once in main. The `.env` symlink is the documented exception to the "never read .env" safety rule - symlinking via `ln -s` is not reading. Layer 2 (optional, project-supplied): `create-session.sh` runs `docs/apex-bootstrap.sh` (preferred) or `.apex/bootstrap.sh` from the worktree root post-symlink if present, for projects that need codegen / install / DB seed beyond the symlink. Non-zero exit is non-fatal (continues to manifest write). Layer 3 (defensive in `verify-build.sh`): when `node_modules` is still absent at step-10 entry (Layer 1 found nothing to symlink, Layer 2 absent or skipped), run the PM's `--frozen-lockfile` install once before lint/build instead of feeding "module not found" to the executor fix-loop. Same fallback hierarchy applies to other languages by extension (`.venv` / `target` / etc.) once their verify-build branches add it.
- **Session token format**: 8-char lowercase hex (short guid generated at step 2 via `openssl rand -hex 4`).
- **cc_session_id resolution**: Claude Code does NOT export the active session id as a bash env var. Every apex script that needs `cc_session_id` resolves through `scripts/get-cc-session-id.sh` (3-step: env-var fast path; then ancestor PID-walk parsing `claude ... --session-id <UUID>` from the process tree - the authoritative resolver that sidesteps the latest-jsonl race; then most-recent-jsonl fallback at `~/.claude/projects/<encoded-cwd>/`, where `<encoded-cwd> = pwd | tr '/.' '--'`, as the legacy off-tree path). Step 2 invokes `create-session.sh --cc-session-id "$(bash scripts/get-cc-session-id.sh)"`.
- **JSON Schema validation helpers**: `scripts/_validate.py` (python module - `producer_validate(data, schema_name)` raises `ValidationError`; `consumer_load(path, schema_name)` returns `None` on missing/invalid; schema dir resolved via `APEX_SCHEMA_DIR` env var if set, otherwise defaults to `skills/apex/schemas/` relative to the module) and `scripts/validate-json.sh <schema-name> <json-path>`. Producer scripts validate before write; orchestrator inline-LLM producers (steps 4, 7) validate immediately after `Write`. Apex hot path falls back to JSON-parse-only when `jsonschema` is not importable (one-line stderr warning).
- **Session manifest schema** (`<worktree>/.claude-tmp/apex-active/{session}.json`): `{session, pid, cc_session_id, worktree_path, branch, base_branch}` (all required). `pid` is the OS process id of the live claude main process - resolved by `scripts/find-claude-pid.sh` (walks up the process tree from the script's `$$` until a process with `comm` basename `claude` is found). `cc_session_id` is the Claude Code session id captured at step 2. `worktree_path` is the absolute path to `<main-worktree>/.apex-worktrees/<session>/`. `branch` is the `apex/<session>` ref the worktree owns. `base_branch` is the branch HEAD was on at step 2 - what `/apex-merge` lands the session back onto. Optional `bump_hint: patch|minor` is populated by step 12 (the orchestrator persists the classified tier into the manifest); the project-side deploy skill picks the highest tier across the batch when bumping VERSION. Worktree isolation removes the sibling-commits-during-our-run scenario, so the `base_branch` field alone anchors every diff downstream: agents derive a `diff_anchor` as `git merge-base $base_branch HEAD` (the apex/<session> fork point), stable from session mint through step 15. No producer step writes a snapshot file - the manifest is the single source of truth.
- **Scope write producers** (single source of truth for `{session}-main-scope.json`, exactly one fires per session): trivial path -> orchestrator inline `Write` at step 3.1; non-trivial path -> `agents/discoverer.md` at step 6.
- **Scope-check pointer**: written immediately after each scope write at `.claude-tmp/apex-active/{session}-scopes/{cc_session_id}.txt` (single-line absolute path to the scope JSON). The PreToolUse hook reads this pointer to gate `Edit` / `Write` / `MultiEdit` / `NotebookEdit`.
- **Trace path schema**: `.claude-tmp/apex-active/{session}-traces/{phase}/{agent}[-{disambiguator}].md` where `{phase}` is `entry` (steps 1-7), `execute` (step 8), `verify` (step 10), or `tail` (step 11). `{disambiguator}` is optional (task-id, attempt-N).
- **Side-effects log** (`.claude-tmp/apex-active/{session}-side-effects.jsonl`): per-line JSON `{"cmd","ts"}` recording each state-mutating Bash command the step-8 executor ran in this worktree (migrations, seeders, codegen producing untracked output, deps installs touching system state). Read-only commands (lint / typecheck / build / test) are excluded. Consumed by `/apex-merge` step 4.5 (`skills/apex-merge/scripts/replay-side-effects.sh`) which aggregates across all merged worktrees, dedupes by verbatim cmd, and surfaces the unique set via AskUserQuestion for replay on the main worktree post-merge. Absent log = no replay candidates for that session (clean text-only diff).
- **scope-check hook** (`skills/apex/scripts/scope-check-hook.sh`): PreToolUse on `Edit` / `Write` / `MultiEdit` / `NotebookEdit`. Bash file operations (`sed -i`, redirection, `cp`, `mv`, etc.) are NOT gated by the hook; subagent and skill prompts must restrict file modifications to the hook-gated tools (convention-enforced at the prompt layer). Resolves the active scope file via on-disk pointer (env-var indirection rejected: Claude Code's Bash tool runs each invocation in a fresh subshell). The hook extracts `session_id` from its stdin event JSON and globs `.claude-tmp/apex-active/*-scopes/{session_id}.txt` (any apex `{session}` matches; in practice exactly one matches the calling session_id). Pointer-miss is a four-way fork: (a) no active main-scope.json in this worktree's apex-active -> pass-through (entry-flow / non-/apex session); (b) active main-scope.json exists AND CWD is inside an apex worktree (`.apex-worktrees/<token>/`) -> enforce it directly (per-worktree isolation guarantees at most one orchestrator per apex-active dir, so no PID disambiguation is needed - the single main-scope is the subagent's parent); (b') active main-scope.json exists BUT CWD is NOT inside a worktree -> pass-through. A main-scope in the MAIN tree's apex-active is always a leaked/stray artifact (every /apex session is worktree-isolated, so a legitimate main-scope never lives in the main tree), and a main-tree pointer-miss editor is an unrelated sibling session (a separate /apex or non-/apex Claude Code session sharing the repo), not a subagent - enforcing the leaked scope against it would block innocent concurrent work. Safety-path fast-path also rejects cross-worktree `.apex-worktrees/<X>/.claude-tmp/...` paths so a subagent in worktree A cannot slip a write into worktree B's apex-active via the generic `.claude-tmp/` rule - those go through the normal `allowed_files` check instead.
- **file-health hook** (`skills/apex/scripts/file-health-hook.sh`): PreToolUse safety net during step 8 execute. Blocks `Edit` / `Write` / `MultiEdit` when the existing file is > 400 LOC AND the change adds > 10 net lines; trivial edits (<= 10 net lines) pass even on > 500-LOC files. Pre-flight wc-l queue at step 8 init handles the > 400 LOC split cases ahead of edits to avoid hot-path stalls.
- **block-destructive hook / NEVER stash** (`skills/apex/scripts/block-destructive-hook.sh`): PreToolUse on `Bash`, uniform across the orchestrator and every subagent (executor, discoverer, screener, reviewer, etc.) - no per-agent contract drift possible. Apex agents must NEVER `git stash` work: per-session worktrees eliminate cross-session sibling overlap, but the orchestrator + co-resident subagents inside ONE worktree share a single working tree, and a bare `git stash` (= `git stash push`) from any of them silently captures EVERY co-resident agent's uncommitted edits into a single stash ref, which presents as catastrophic work loss for parallel siblings. The hook denies all stash-creation forms (bare / `push` / `save` / `create` / `store` / any flag form like `-p` `-u` `-m`); only read-only (`list` / `show`) stay allowed, `pop` has its own deny. `git stash apply` / `git stash branch` are ALSO denied (these are stash subcommands, not `git branch` / `git worktree add -b`, which never reach the parser): with creation blocked, an agent owns no self-created stash, so a bare `git stash apply` defaults to `stash@{0}` - which can only be a pre-existing USER stash - and 3-way-merges it into the working tree, injecting conflict markers (real incident). Agents needing a clean tree must commit, not stash.
- **step-read gate hook (B/R3, ARMED at session mint, ENFORCING once the orchestrator emits `metadata.step`)** (`skills/apex/scripts/step-read-gate-hook.sh`): one script wired at three touchpoints - PreToolUse on `TaskUpdate` (stamps `active_step`/`active_since` when `status==in_progress` and `tool_input.metadata.step` is set), PostToolUse on `Read` (stamps `read_steps[NN]` when the path matches `skills/apex/steps/NN-*.md`), and PreToolUse on the work tools `Edit` / `Write` / `MultiEdit` / `NotebookEdit` / `Task` / `Bash` (the GATE). It enforces the lazy-load read-before-work invariant once B exists: after step NN becomes active, the step's contract sub-file must be Read before that step's first work tool, else the work tool is denied - turning the documented read-once drift into a fail-closed check. State lives at `.claude-tmp/apex-active/{session}-step-progress.json`; its EXISTENCE is the arming sentinel, now created by `create-session.sh` at session mint (step 2), so the hook is ARMED for every apex session. With Workstream B's `steps/NN-*.md` contract files extracted and `skills/apex/SKILL.md` "Per-step dispatch" now stamping `active_step` (via `TaskUpdate` `metadata.step`) before each step's contract Read, the gate ENFORCES read-before-work for real /apex sessions; the empirical R3-a perf + no-false-denies sign-off over a captured standard run is DONE (VERSION 10.0.0; replayed via `skills/apex/scripts/replay-canary.sh` over `skills/apex/scripts/fixtures/apex-step-read-fixture.jsonl`). Orchestrator-only (acts only on a direct scope-pointer hit; subagents are never gated), fail-OPEN on unset `active_step` / missing state / any parse error, fail-CLOSED only when `active_step` is set but its contract is unread since activation. Companions: `skills/apex/scripts/transcript-step-read-check.py` (post-run canary asserting the same invariant) + `skills/admin-apex/scripts/test-step-gate.sh` (fixtures).
- **audit-and-rescope (step 11)**: when a tail agent (`documentation.md` / `learn.md`) flags drift in adjacent, pattern-aligned files outside the planned scope, the orchestrator re-scopes the session (updates `{session}-main-scope.json` + scope-check pointer) and fixes inline in the same tail phase rather than spawning a new /apex run. Limited to same convention / file family (e.g., a docs file paired with the code module just touched); cross-domain drift escalates back to the user.
- **Parallel /apex on one project**: two Claude Code sessions running /apex against the same project repo mint independent worktrees at `<main>/.apex-worktrees/<sessionA>/` and `<main>/.apex-worktrees/<sessionB>/`, each with its own branch (`apex/<sessionA>`, `apex/<sessionB>`), index, working tree, and `.claude-tmp/apex-active/`. The two sessions never observe each other's edits during execution. Each lands back on its recorded `base_branch` via its own `/apex-merge` run; if the two scopes overlap textually, the second merge surfaces conflicts in the normal `/apex-merge` step 4 flow (resolver agent + AskUserQuestion). No special coordination is needed at session mint - worktree isolation is the coordination.
- **Spawn-prompt tone (Opus 4.7 / Sonnet 4.6)**: apex orchestrator + agent prompts target models that over-trigger on legacy anti-laziness over-prompting. State instructions in plain declarative phrasing; reserve emphatic `CRITICAL` / `you MUST` / `NEVER` for genuine safety / contract invariants (scope-check, destructive-op, fail-closed), not as routine reinforcement. Newer models follow instructions literally - explicit scope ("apply to every X, not just the first") beats volume. Tightening over-emphatic prose toward plain phrasing is an in-band `/apex-improve` semantic edit, never an additive rule.
- **Lean prose (no negative-scope, no incident-narrative)**: document what a component does now plus where related work lives (routing pointers). Do NOT add `What X does NOT do` / `Out of scope` disclaimer sections or scope-negative bullets (`Does NOT touch project code`) - an unstated non-responsibility is not a gap. Do NOT justify a rule by recounting the incident that motivated it (the bug story, `was X under the old prefix`, a raw `reflector <hex>` session hash); state the rule positively and let git history + the commit message hold the why - cite a cluster slug or nothing. Operational negatives that govern current behavior (`never blind-edit`, `fail closed on missing secrets`, hard caps) are rules, not disclaimers - keep them. Enforced deterministically at audit + polish by two `audit-detectors.py` re-bloat guards - `hash-roster` for inline session hashes, `negative-scope` for disclaimer sections / `Does NOT ...` bullets - backed by editing discipline at apply time (`apex-improve/apply.md`, `admin-apex/evolve.md`) and reflection time (`agents/reflector.md`).
- **Tool-output integrity (never act on unread output)**: every factual claim an apex agent makes - file content, exit code, line count, push / commit result - must trace to a tool result actually read THIS turn; never infer, assume, or fabricate output that was not cleanly received. **Parallel-batch attribution**: when one assistant turn fires multiple tool calls (multi-block batch, `run_in_background` fan-out, or a piped / `&`-parallel shell command), their outputs can interleave or arrive out of order - bind each claim to the specific call whose result you actually read, never by position or adjacency; if a batch's output is interleaved, doubled, or its ownership is ambiguous, RE-RUN that single check in isolation (one foreground call) before asserting off it - a membership / state claim read off an interleaved batch (`commit X IS in main`, `file Y exists`, `N tests passed`) is the canonical misread (a git history-membership claim was asserted off garbled interleaved parallel-batch output, then self-corrected only on a clean serial re-read). Unreadable output (garbled, doubled lines, "oop wel..."-style garbage, empty, or unparseable) is a HARD STOP, not a proceed signal: re-run the read ONCE; if still corrupt, redirect the command's output to a file and read it with the `Read` tool; if that read is STILL garbled, halt and surface to the user rather than continuing blind. Gate every destructive / outward-facing step (commit, push, `rm`, truncate, `git restore`) on a CLEAN precondition read - an unreadable verifying read blocks the irreversible step, never "proceed anyway". Before planning edits off a signal / state file (`apex-workflow-improvements.md`, a drift report, a manifest), cite real line numbers / tokens present in the actual read; if the tokens being planned against are absent from what was read, abort the analysis rather than inventing them. Report a non-zero exit / failed push / failed commit as a failure with its evidence immediately - never smooth a failure into "done".
- **Goal-coupling vocabulary (step 8.2; referenced by `steps/08-execute.md` B2 and the step-13 reflector)**: **collapse criteria (interlocked goals)** - when 2+ goals share the same parameter / config surface (same shared constant, seeder file, or schema definition) AND scope intersection >= 50%, the orchestrator MAY collapse them into one executor task carrying the joined goal text + union scope (`deviation_note: "interlocked: <one-line>"`); collapse is forbidden when the goals are independent (disjoint scope) or intersection is < 50%. **same-domain-noun coupling (intent-coupled goals)** - when 2+ goals reference the same dominant domain noun (a token surviving the deterministic stopword/min-length filter and appearing in 2+ goal strings) they are coupled by intent even with disjoint grep-level `allowed_files`; serialize them pre-dispatch as one follow-up task (never parallel + redispatch). Audit-then-act pairs (one goal validates state, the next mutates it) and goals that each cross-link the SAME canonical source doc are the canonical cases - merge upfront so the shared surface is read once. **no self-validation** - each executor does one thing for one goal; a same-context second pass over its own work is biased and yields little signal; errors are caught by step-10 verify-build, and cross-goal correctness is deferred to a future context-isolated semantic-validator. The reflector reads these definitions when classifying a collapse as legitimate vs scope-creep.
- **Bump tiers (step-12 diff classification; referenced by `steps/03-trivial.md`, `steps/12-commit.md`, `scripts/bump-version.sh`)**: **minor** = new feature, new public symbol / route / component, additive, OR breaking API change (removed/renamed public symbol, contract change, schema migration); **patch** = bug fix, refactor, tweak, internal-only change. **major** is user-set only - /apex never emits it.
- **Deterministic keyword recipe (step-5 lessons grep + step-6 discovery expansion + step-8.2 per-task noun-set split; scripted in `skills/apex/scripts/discovery-expand.sh` for step 6)**: lowercase + tokenize on whitespace+punctuation, drop the stopword set `the|a|an|and|or|of|to|in|for|on|with|is|are|was|were|be|by|that|this|these|those|it|as|at|from|verify|ensure|make|sure|check|each|all|any|every`, drop tokens shorter than 4 chars, dedupe across goals. Same `goals[]` -> same keyword set, run-to-run. Step 5 caps at the top 8 keys by document-order (halve to top 4 + re-screen once on screener `truncated=true`); the step-6 expansion runs every deterministic Glob/Grep sibling/consumer/doc clause in one `discovery-expand.sh` call (per-clause caps in the script) so the discoverer no longer walks them one tool-call at a time.
- **`/apex-fix` verify scope**: `/apex-fix` invokes `verify-build.sh` WITHOUT `--with-tests` or `--in-scope-only` (whole-repo lint/build fix; tests and session-scope partition are out of scope for the standalone fix loop, which has no apex session manifest). `/apex` step 10 invokes WITH `--with-tests --in-scope-only`.

## Apex flow

Per-step runtime contracts are lazy-loaded from `skills/apex/steps/NN-*.md` (the orchestrator Reads each before its step - B/R3 read-before-work). The routing summary (skill / agent / script per step + the conditions that select each) lives in `apex-core-overview.md`. This index gives each step's purpose + canonical home; cross-cutting rules are in ## Conventions above and failure / cleanup in ## Failure handling below.

0. **Initialisation** - /apex orchestrator (`skills/apex/SKILL.md`) TaskCreates tasks 1-15 (deferred-tool guard: load `TaskCreate`/`TaskUpdate`/`TaskList` via `ToolSearch` first; the trivial branch marks 4-13 completed-skipped). Contract: `skills/apex/SKILL.md` Step 0.
1. **Analyze + read project-context** - inline; AskUserQuestion if ambiguous (abort = clean exit, no manifest yet); forms the `goals[]` decomposition expectation that drives steps 6/7/8.2/13/15. Contract: `steps/01-analyze.md`.
2. **Create session manifest** - `scripts/create-session.sh` mints the `{session}` token + an unconditional worktree at `.apex-worktrees/<session>/` on branch `apex/<session>`; token-provenance hard gate (thread the EXACT stdout token, never fabricate). Contract: `steps/02-manifest.md`.
3. **Trivial pre-flight** - conservative gate (single named file, no new public symbol, no cross-file dep; ANY ambiguity = non-trivial); on trivial, 3.1 does the inline edit + lightweight commit and jumps to step 14. Contract: `steps/03-trivial.md`.
4. **Hypothesis** - inline; emits `original_prompt` / `hypothesis` / `complexity_hint` / `alternatives[]` / `goals[]` (+ optional `discovered_paths`); producer-validates `hypothesis.schema.json`. Contract: `steps/04-hypothesis.md`.
5. **Load lessons + project docs** - `scripts/grep-lessons.sh` (deterministic keywords, see ## Conventions) + the K=25 screener gate / `agents/lesson-screener.md` -> `{session}-lesson-screened.json`. Contract: `steps/05-lessons.md`.
6. **Discovery** - `agents/discoverer.md` + `scripts/discovery-cache.sh` + `scripts/discovery-expand.sh`; cache-check-first, else the LSP -> `discovery-expand.sh` (one-call deterministic Glob/Grep sibling/consumer/doc expansion) -> screener cascade -> `{session}-main-scope.json` + scope-check pointer. Contract: `steps/06-discovery.md`.
7. **Economy pre-flight** - inline deterministic rule (no AI / subagent) -> `{session}-tier.json` (`economy` | `standard`); drives step-8 executor model + the step-9 / step-11 skips. Contract: `steps/07-economy.md`.
8. **Execute** - goals-driven task split (8.2: collapse / same-domain-noun coupling per ## Conventions; B0.7 scout; B1 / B2 size ceilings), parallel `agents/executor.md` dispatch (8.3) with self-report reconciliation; dispatch-only (orchestrator never inline-edits scope files). Contract: `steps/08-execute.md`.
9. **Polish** - `agents/polish.md`; standard always runs, economy skips; in-scope-only cleanup (touched INTERSECT `allowed_files`). Contract: `steps/09-polish.md`.
10. **Verify** - `scripts/verify-build.sh --with-tests --in-scope-only` (lint + build + scoped tests; lint treats warnings as errors + auto-fix pre-pass); fix-loop via `agents/executor.md` (always Sonnet, cap 3). Contract: `steps/10-verify.md`.
10.5. **Review** (only after step 10 exits 0) - deterministic gate (standard tier; size / complexity / doc-consistency triggers); `agents/reviewer.md` scans the diff INTERSECT `allowed_files` against CLAUDE.md rules, cap 5 findings, max 2 reviews + 1 fix. Contract: `steps/10-verify.md` (Step 10.5) + `agents/reviewer.md`.
11. **Tail** - `agents/documentation.md` (unless `hypothesis.mode == "code-only-no-docs"`) + `agents/learn.md` (standard only, behind the difficulty gate). Contract: `steps/11-tail.md`.
12. **Commit + persist bump_hint** - inline `git add -A; commit; push apex/<session>`; classify `bump_hint` (## Conventions bump tiers; never major); scope-drift pre-commit emit. Contract: `steps/12-commit.md`.
13. **Self-reflect** - `scripts/reflect-traces.sh` heuristics + `agents/reflector.md` (Sonnet, background, silent; owns the post-reflect `cleanup-session.sh`; non-convergence + oversized-dispatch detection). Contract: `steps/13-reflect.md` + `agents/reflector.md`.
14. **Cleanup session** (trivial path only; non-trivial paths clean up via the step-13 reflector) - `scripts/cleanup-session.sh` (worktree-only fork on state). Contract: `steps/14-cleanup.md`.
15. **Inline summary** - fully deterministic (no LLM hop); emits the fixed section set + closes the loop (`TaskUpdate` 15 -> completed); owns the 15.0 cd-back sweep. Contract: `steps/15-summary.md`.

## Failure handling

- `cleanup-session.sh` is idempotent: exit 0 on partial cleanup with warnings to stderr. Worktree-only - reads the manifest's `worktree_path` / `branch` / `base_branch` and forks on worktree state (clean+no-commits-past-base = `git worktree remove --force` + `git branch -D`; clean+commits = keep, warn awaiting `/apex-merge`; dirty = keep, warn). The worktree sweep removes manifest + scope + traces + tier + screened + hypothesis + every other `{session}-*` artifact atomically because they all live inside the worktree subtree. **APEX_ACTIVE resolution** (priority chain, first non-empty wins): `--apex-active-dir <abs>` flag > `APEX_ACTIVE_DIR` env > `$CLAUDE_PROJECT_DIR/.claude-tmp/apex-active` > `$PWD/.claude-tmp/apex-active`. Background reflector subagents (apex step 13) may not inherit project CWD; pass `--apex-active-dir` explicitly from the spawn prompt. **Stdout / cd-back contract**: on every branch where `worktree_path` resolves, the script prints the absolute main-worktree path on the last stdout line. Mid-/apex abort callers MUST capture this and `cd` there so the orchestrator shell leaves the (possibly removed) worktree subdirectory. Normal-flow cd-back is owned by step 15.0 below; the prior step-13 / step-14 mid-paragraph one-liners drifted across long-context runs and were collapsed into 15.0. **Step 15.0 cd-back sweep**: step 15 (inline summary; always runs on every non-aborted path) opens with an idempotent `dirname(dirname(WORKTREE_PATH))` cd-back BEFORE any reads / emits - sole canonical post-/apex cd-back guard. Empty stdout (manifest missing / worktree_path gone) -> the inline summary falls back to `dirname(dirname(WORKTREE_PATH))` from step-2 working memory.
- `session-end-hook.sh` wraps `cleanup-session.sh`. SessionEnd mode reads the stdin event's `session_id`, scans `<main>/.apex-worktrees/*/.claude-tmp/apex-active/*.json` for a matching `cc_session_id`, and forwards the located apex-active dir via `--apex-active-dir` to `cleanup-session.sh`. After the matched cleanup it also sweeps sibling `.apex-worktrees/<token>/` dirs (`sweep_stale_worktrees`): manifest-less crash-orphans are removed inline, and manifest-present dirs whose owning session is no longer live (recorded `pid` dead or recycled to non-`claude`) get the `cleanup-session.sh` keep/remove decision re-run - the sole reaper for a fully-merged (clean + no commits past base) worktree the owning session's own step-13/14 cleanup left behind (branch integrated outside `/apex-merge`, or its step-5 cleanup interrupted); unmerged / dirty / live-owner worktrees are preserved. It then runs `sweep-orphan-artifacts.sh` against the MAIN worktree's apex-active as a defense-in-depth reap of manifest-absent `{session}-*` siblings (age-gated; live + in-flight sessions untouched - see below). Manual mode (mid-/apex abort) takes a positional session token. Forwards cleanup-session.sh stdout verbatim so manual-mode callers receive the cd-back target.
- **Mid-/apex abort cleanup**: any orchestrator exit bypassing step 14 runs `session-end-hook.sh {session}` inline. Triggers:
  - AskUserQuestion-abort at step 1 (no manifest yet -> skip session-end-hook)
  - step 6 cascade-empty + abort
  - step 6 cascade-empty + proceed-with-prompt-paths but zero validated paths
  - step 10 verify cap-3 exhaustion (if user opts to abort)
  - any unexpected error path
- The Claude Code SessionEnd hook is the catch-all when the entire Claude Code session ends; the inline call handles the "user aborts /apex but stays in the same Claude Code session" case so the worktree-resident manifest is swept and the worktree dir is cleaned.
- `sweep-orphan-artifacts.sh` (under `skills/apex/scripts/`) plugs the `{token}-* without {token}.json` leak: when a manifest has been swept (or never written) but crash-orphaned sibling artifacts remain (inventory / drift-report / trace scratch), this helper removes them once mtime exceeds `--age-hours` (default 24). `{run}-deferred-findings.json` is EXEMPT - the apex-improve / admin-apex backlog is session-spanning and kept across idle gaps (analyze.md consumes + finalize.md prunes it, so it never accumulates). Wired into `sweep-stale-runs.sh` end (admin-apex-active) so each admin-apex run inherits a clean workspace, AND into `session-end-hook.sh`'s SessionEnd path against the MAIN worktree's apex-active as defense-in-depth: per-worktree isolation should keep that dir empty (`create-session.sh` mints an empty worktree-resident apex-active by construction), but a partial `cleanup-session.sh` worktree-remove or a stray main-anchored `{session}-*` write can still strand siblings whose manifest is gone - the `--age-hours` + manifest-absent guards keep live (manifest present) and in-flight (<24h) sessions untouched. Best-effort; never blocks.
- `discovery-cache.sh prune` evicts cache entries with mtime older than `TTL_DAYS` (7) globally. Without it, entries only evict per-key on `check` reads of the same prompt, so the `apex-discovery-cache/` directory grows unbounded when prompts are not re-issued. Wired into `create-session.sh` startup. HEAD-divergence eviction continues to fire per-key on read (cheap; touches git only when the prompt is checked).
