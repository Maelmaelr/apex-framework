# /apex

Apex is the main orchestrator in the main session.

For a summary of steps, skill / agent / script used, and routing conditions, see `apex-core-overview.md`.

## Tiers (cross-cutting)

- **trivial** decided at step 3 (conservative pre-flight; ANY ambiguity = non-trivial). Step 3.1 inline single Edit/Write -> jump to step 14. Skips 4-13.
- **economy** decided at step 7 by deterministic rule. Step 8 executors run on Sonnet; **step 9 polish skipped**; step 11 skips `learn`.
- **standard** default at step 7 when the deterministic rule does not classify economy. Step 8 executors run on the main session model; full tail.

**Step 13 reflector is background** in non-trivial paths (economy + standard); the reflector owns the post-reflect `cleanup-session.sh --post-success` call as its final action. Step 14 only runs on the trivial path (where step 13 was skipped). Step 15's inline summary is fully deterministic (no LLM hop, no git audit pass).

## Conventions

- **Standard safety paths** (always allowed in any scope artifact): `.claude-tmp/`, `~/.claude/tmp/`, `/tmp/{session}-*`, project `docs/**`, any `README*` file at any depth, and any `VERSION` file at any depth (basename match; consumed by step 12 git-sync's inline VERSION bump post-agent and by orchestrator post-agent inline bumps - reflector 00bac875 surfaced the gate denial). The set is closed. `.env*` and `.git/` are NEVER safety paths regardless of scope contents.
- **Project context** (architecture entry point): `<project-root>/docs/project-context.md`. Read at step 1 (best-effort; absent = silent skip; cap read at ~200 lines). Cached for downstream steps via working memory; consumers re-read directly when their work requires it.
- **Project lessons paths**: `<project-root>/.claude/lessons-index.md` (curated index; consumed by step 5 `grep-lessons.sh`), `<project-root>/.claude/lessons.md` (curated body), `<project-root>/.claude/lessons-archive.md` (older / superseded). `learn.md` (step 11) appends novel patterns to `.claude-tmp/lessons-tmp.md`; curation is out of scope for /apex.
- **Project CLAUDE.md budget**: `<project-root>/CLAUDE.md` loads on every turn; Claude Code degrades past a ~40k-char hard cliff (the warning the user sees). Apex soft ceiling = 30k chars. Every apex writer of project CLAUDE.md enforces this: `apex-init/create.md` seeds well under it, `apex-lessons/route.md` gates each Project-CLAUDE.md route on it (route to `docs/` instead on breach; evict superseded section bodies to `docs/` leaving a one-line pointer until back under 30k), and `agents/documentation.md` relocates detail to `docs/` rather than growing it. Leanness over completeness - CLAUDE.md holds broadly-applicable rules and pointers, never accumulated detail. Global `~/.claude/CLAUDE.md` is user-curated and exempt from auto-eviction.
- **Session token format**: 8-char lowercase hex (short guid generated at step 2 via `openssl rand -hex 4`).
- **cc_session_id resolution**: Claude Code does NOT export the active session id as a bash env var. Every apex script that needs `cc_session_id` resolves through `scripts/get-cc-session-id.sh` (env-var fast path then most-recent-jsonl fallback at `~/.claude/projects/<encoded-cwd>/`, where `<encoded-cwd> = pwd | tr '/.' '--'`). Step 2 invokes `create-session.sh --cc-session-id "$(bash scripts/get-cc-session-id.sh)"`.
- **JSON Schema validation helpers**: `scripts/_validate.py` (python module - `producer_validate(data, schema_name)` raises `ValidationError`; `consumer_load(path, schema_name)` returns `None` on missing/invalid; schema dir resolved via `APEX_SCHEMA_DIR` env var if set, otherwise defaults to `skills/apex/schemas/` relative to the module) and `scripts/validate-json.sh <schema-name> <json-path>`. Producer scripts validate before write; orchestrator inline-LLM producers (steps 4, 7) validate immediately after `Write`. Apex hot path falls back to JSON-parse-only when `jsonschema` is not importable (one-line stderr warning).
- **Session manifest schema** (`.claude-tmp/apex-active/{session}.json`): `{session, pid, cc_session_id}` plus an optional `effective_baseline_sha` written ONLY when a mid-run baseline supersede is detected at step 8 (a sibling /apex committed during this run). `pid` is the OS process id of the live claude main process - resolved by `scripts/find-claude-pid.sh` (walks up the process tree from the script's `$$` until a process with `comm` basename `claude` is found). `cc_session_id` is the Claude Code session id captured at step 2. `effective_baseline_sha`, when present, is the deterministic diff base for steps 9-12 and every downstream subagent spawn (polish / documentation / learn / git-sync / reflector) reads it in place of `baseline.head_sha`; absent = baseline never superseded, use `baseline.head_sha`. **Worktree-mode optional fields** (Phase 2 opt-in via env `APEX_WORKTREE=1` at step 2): `worktree_path` (absolute path to `<main-worktree>/.apex-worktrees/<session>/`), `branch` (`apex/<session>` ref the worktree owns), `base_branch` (the branch HEAD was on at step 2 - what `/apex-merge` lands the session back onto). Optional `bump_hint: patch|minor` is reserved for the future `/apex-merge`-owned batched VERSION bump; current step 12 still bumps directly and does not populate it. Pre-migration manifests omit all four worktree fields and validate identically.
- **Scope write producers** (single source of truth for `{session}-main-scope.json`, exactly one fires per session): trivial path -> orchestrator inline `Write` at step 3.1; non-trivial path -> `agents/discoverer.md` at step 6.
- **Scope-check pointer**: written immediately after each scope write at `.claude-tmp/apex-active/{session}-scopes/{cc_session_id}.txt` (single-line absolute path to the scope JSON). The PreToolUse hook reads this pointer to gate `Edit` / `Write` / `MultiEdit` / `NotebookEdit`.
- **Trace path schema**: `.claude-tmp/apex-active/{session}-traces/{phase}/{agent}[-{disambiguator}].md` where `{phase}` is `entry` (steps 1-7), `execute` (step 8), `verify` (step 10), or `tail` (step 11). `{disambiguator}` is optional (task-id, attempt-N).
- **scope-check hook** (`skills/apex/scripts/scope-check-hook.sh`): PreToolUse on `Edit` / `Write` / `MultiEdit` / `NotebookEdit`. Bash file operations (`sed -i`, redirection, `cp`, `mv`, etc.) are NOT gated by the hook; subagent and skill prompts must restrict file modifications to the hook-gated tools (convention-enforced at the prompt layer). Resolves the active scope file via on-disk pointer (env-var indirection rejected: Claude Code's Bash tool runs each invocation in a fresh subshell). The hook extracts `session_id` from its stdin event JSON and globs `.claude-tmp/apex-active/*-scopes/{session_id}.txt` (any apex `{session}` matches; in practice exactly one matches the calling session_id). Pointer-miss is tri-state: (a) no active main-scope.json anywhere -> pass-through (entry-flow / non-/apex session); (b) active main-scope.json exists -> walk the process tree to the calling claude pid via `find-claude-pid.sh` and match against each apex manifest's recorded `pid`. Match -> enforce that orchestrator's scope (subagent-of-this-orchestrator); no match -> pass-through (sibling apex sessions running in other claude processes do not gate this one). Failure to resolve a claude ancestor (non-standard launcher) also passes through.
- **file-health hook** (`skills/apex/scripts/file-health-hook.sh`): PreToolUse safety net during step 8 execute. Blocks `Edit` / `Write` on files > 500 LOC; nudges to split first. Pre-flight wc-l queue at step 8 init handles the > 400 LOC cases ahead of edits to avoid hot-path stalls.
- **block-destructive hook / NEVER stash** (`skills/apex/scripts/block-destructive-hook.sh`): PreToolUse on `Bash`, uniform across the orchestrator and every subagent (executor, git-sync, etc.) - no per-agent contract drift possible. Apex agents must NEVER `git stash` work: a bare `git stash` (= `git stash push`) in the shared worktree silently captures EVERY concurrent agent's uncommitted edits into a stash ref, which presents as catastrophic work loss for parallel siblings. The hook denies all stash-creation forms (bare / `push` / `save` / `create` / `store` / any flag form like `-p` `-u` `-m`); read-only (`list` / `show`) and non-destructive recovery (`apply` / `branch`) stay allowed, `pop` has its own deny. Agents needing a clean tree must commit, not stash.
- **audit-and-rescope (step 11)**: when a tail agent (`documentation.md` / `learn.md`) flags drift in adjacent, pattern-aligned files outside the planned scope, the orchestrator re-scopes the session (updates `{session}-main-scope.json` + scope-check pointer) and fixes inline in the same tail phase rather than spawning a new /apex run. Limited to same convention / file family (e.g., a docs file paired with the code module just touched); cross-domain drift escalates back to the user.
- **Spawn-prompt tone (Opus 4.7 / Sonnet 4.6)**: apex orchestrator + agent prompts target models that over-trigger on legacy anti-laziness over-prompting. State instructions in plain declarative phrasing; reserve emphatic `CRITICAL` / `you MUST` / `NEVER` for genuine safety / contract invariants (scope-check, destructive-op, fail-closed), not as routine reinforcement. Newer models follow instructions literally - explicit scope ("apply to every X, not just the first") beats volume. Tightening over-emphatic prose toward plain phrasing is an in-band `/apex-improve` semantic edit, never an additive rule.

## Apex flow

0. Initialisation
   - /apex (main orchestrator) | `~/.claude/skills/apex/SKILL.md`
     - TaskCreate tasks 1 - 15 (15 always queued; trivial branch at step 3 marks 4 - 13 completed-skipped)

1. Analyze + read project-context.md
   - inline task prompt
     - analyzes prompt
     - AskUserQuestion if ambiguous; abort = clean exit (no manifest yet)
     - reads `<project-root>/docs/project-context.md` if present (best-effort; absent = silent skip; cap read at ~200 lines)
     - **goals decomposition expectation**: when forming the working interpretation, expect step 4 to emit a `goals[]` array (1..N items). Single-task prompts ("fix the typo in login.tsx") -> one goal verbatim. Multi-task / audit prompts ("make sure all kie image-gen models have settings + costs wired") -> N enumerated goals, each a discrete actionable check. `goals.length` drives downstream behaviour at step 6 (top-K), step 7 (deterministic tier rule), step 8.2 (per-goal task split), step 13 (non-convergence detection), step 15 (per-goal summary). Internal bias only at step 1; no user-visible change.
     - **plan-completed early-exit (continue-file form)**: when `original_prompt` is a `continue: <plan-file>` form and every top-level goal in that plan file is already `[x]` / DONE, this is a structurally distinct prompt from a fresh goal - the prompt-hash collides with prior runs of the same plan and resolves to a different file set each time, which the step-13 non-convergence guard catches only post-hoc. Surface it as a named case here: AskUserQuestion (`close-plan-nothing-to-do` | `narrow-to-explicitly-deferred-items` | `re-spec`); dismiss = `close-plan-nothing-to-do` (clean exit, no manifest yet). When the plan carries a status section that may be stale, field-presence is NOT proof of completion - run the plan's own encoded acceptance tests as the satisfiability discriminator before declaring it complete (reflector cluster ff441791 / f5d3280a / 4c92e825 / b2716ff4 / 35b42f2b: continue-form prompt-hash collided across 5 sessions touching 0/9/12/53/14 files; 2c226d56: a stale status section needed acceptance-test proof, not field-presence).

2. Create session manifest | Blocked by #1
   - script `scripts/create-session.sh --cc-session-id "$(bash scripts/get-cc-session-id.sh)"`
     - exit 0: `{session}` token to stdout; manifest written + producer-validated against `manifest.schema.json`
     - exit 10: overlap detected. Script writes detected state to stderr (active / stale manifests). Orchestrator branches on parsed state:
       - **stale-only** (active absent, stale present): auto-cleanup-and-proceed without prompting. For each stale token: `bash scripts/session-end-hook.sh <stale-token> --foreign`; then re-run `create-session.sh`. The `--foreign` flag arms `cleanup-session.sh`'s live-PID guard against sibling classifier bugs.
       - **active-detected**: AskUserQuestion (`abort` always present; `proceed alongside` always present; `cleanup-stale-and-proceed` only if stale also present; dismiss/cancel = abort). On abort: no manifest exists yet, so `session-end-hook.sh` is skipped; exit cleanly.
     - **Worktree mode (Phase 2 opt-in)**: env `APEX_WORKTREE=1` instructs `create-session.sh` to additionally capture `base_branch = git symbolic-ref --short HEAD`, create the worktree at `<main-worktree>/.apex-worktrees/<session>/` on branch `apex/<session>` off HEAD, `cd` into it, and persist `{worktree_path, branch, base_branch}` in the manifest (per `manifest.schema.json` worktree-mode optional fields). All subsequent /apex steps execute inside the worktree (isolated `.claude-tmp/apex-active/`, isolated index, isolated working tree). Nested-worktree guard refuses to start from a secondary worktree. `cleanup-session.sh` reads `worktree_path` and forks a worktree-aware branch (clean+no-commits-past-base = `git worktree remove --force` + `git branch -D`; clean+commits = keep, warn awaiting `/apex-merge`; dirty = keep, warn). `session-end-hook.sh` extends its manifest scan to `<main>/.apex-worktrees/*/.claude-tmp/apex-active/*.json` and forwards `--apex-active-dir` so cleanup reaches the worktree-resident manifest; in worktree mode the belt-and-suspenders `rm -f hypothesis.json` is skipped (worktree-remove subsumes it on the clean+no-commits path; manifest+hypothesis are preserved on the keep paths for `/apex-merge`). Integration is the new `/apex-merge` skill (`skills/apex-merge/SKILL.md`; manual trigger from the main worktree). `APEX_WORKTREE` unset / 0 keeps pre-migration behavior intact.

3. Trivial pre-flight | Blocked by #2
   - inline task prompt
     - **Trivial = ALL of**: single file edit (or single new file), file path explicitly named in `original_prompt`, no new public symbol / endpoint / component, no cross-file dependency. **ANY ambiguity = non-trivial.**
     - **Verb-pattern relaxation**: when `original_prompt` matches `/^\s*(rename|format|fix typos?|reword|add (a )?comment|remove (a )?comment|update copy|update string)\b/i`, the path-naming requirement is relaxed: if no path is named, a single inline `Glob` for the most specific noun in the prompt qualifies the prompt iff exactly one match returns (zero or 2+ matches = non-trivial). All other trivial constraints (no new public symbol, no cross-file dep, ANY ambiguity disqualifies) still apply. Pure edit-only prompts ("rename `foo` to `bar`", "fix typo in landing copy") thus reach step 3.1 and skip 4-13.
   - if trivial:
     - **3.1** orchestrator performs the inline `Edit` / `Write` directly. Before the edit, orchestrator writes `{session}-main-scope.json` inline (`allowed_files = [<the single file>] + safety paths`) and writes the scope-check pointer. Orchestrator also writes a **minimal hypothesis stub** at `.claude-tmp/apex-active/{session}-hypothesis.json` (`original_prompt` verbatim; `hypothesis` = one-line restatement; `complexity_hint = "low"`; `alternatives = [{interpretation: original_prompt, status: "kept", reason: "trivial path"}]`; producer-validates against `hypothesis.schema.json`) so step 15's summary contract stays uniform across trivial / non-trivial. After the edit, jumps to task 14.
     - **trivial trade-off**: skips verify (10), commit (12), reflect (13). The conservative gate (single named file, no new public symbol, no cross-file dep, ANY ambiguity disqualifies) keeps the edit reversible and small; the user owns lint/build verification and the `git add+commit` afterwards. Misclassification is on the gate, not the trivial path.
     - tasks 4 - 13 marked completed-skipped so TaskList reflects reality.

4. Hypothesis | Blocked by #3

     - emits `original_prompt` (verbatim user prompt - preserves wording for downstream reflector and step 15 summary; do NOT paraphrase)

Same prompt -> same goals[] (deterministic from prompt + step 1's bias hint), which is what makes the per-goal split at step 8.2 idempotent across re-runs. ## Failure handling

- `cleanup-session.sh` is idempotent: exit 0 on partial cleanup with warnings to stderr. Live-session guard refuses cleanup if manifest.pid is alive AND `ps -o comm=` matches `claude`. `--post-success` bypasses the guard for trusted own-session callers. Sweeps the manifest plus every `{session}-*` sibling via glob (excluding `{session}-hypothesis.json`, which step 15 consumes); future artifact kinds are auto-covered without re-editing the script. **APEX_ACTIVE resolution** (priority chain, first non-empty wins): `--apex-active-dir <abs>` flag > `APEX_ACTIVE_DIR` env > `$CLAUDE_PROJECT_DIR/.claude-tmp/apex-active` > `$PWD/.claude-tmp/apex-active`. Background reflector subagents (apex step 13) and SessionEnd hooks may not inherit project CWD; the script emits a stderr warning when the resolved location holds neither manifest nor sibling, so silent no-ops surface in `~/.claude/tmp/reflector-errors.log` instead of orphaning artifacts (reflector e0f5b897).
- `session-end-hook.sh` wraps `cleanup-session.sh` and additionally removes `{session}-hypothesis.json`. Manual mode without `--foreign` passes `--post-success` to `cleanup-session.sh` (mid-flow abort = trusted own-session caller); with `--foreign` (step 2 cleanup-stale-and-proceed per-stale invocation), the flag is omitted so the live-PID guard fires defensively. Forwards its resolved APEX_ACTIVE via `--apex-active-dir` so the child cleanup-session.sh agrees on the target directory regardless of resolution chain.
- **Mid-/apex abort cleanup**: any orchestrator exit bypassing step 14 runs `session-end-hook.sh {session}` inline. Triggers:
  - AskUserQuestion-abort at step 1 (no manifest yet -> skip session-end-hook)
  - AskUserQuestion-abort at step 2 active-detected (no manifest written for this session -> skip)
  - step 6 cascade-empty + abort
  - step 6 cascade-empty + proceed-with-prompt-paths but zero validated paths
  - step 8 conflict-check-abort
  - step 10 verify cap-3 exhaustion (if user opts to abort)
  - any unexpected error path
- The Claude Code SessionEnd hook is the catch-all when the entire Claude Code session ends; the inline call handles the "user aborts /apex but stays in the same Claude Code session" case so the manifest does not orphan and trigger false-positive concurrency detection from sibling /apex calls.
- `sweep-orphan-artifacts.sh` (under `skills/apex/scripts/`) plugs the `{token}-* without {token}.json` leak: when a manifest has been swept (or never written) but sibling artifacts remain (e.g., apex-improve's session-spanning `{run}-deferred-findings.json` that survives `cleanup-run.sh`), this helper removes them once mtime exceeds `--age-hours` (default 24). Wired into `create-session.sh` startup (apex-active) and `sweep-stale-runs.sh` end (admin-apex-active) so each new run inherits a clean workspace. Best-effort; never blocks. The age threshold is what makes the sweep safe under sibling concurrency: an in-flight producer that writes siblings before its manifest is never raced.
- `discovery-cache.sh prune` evicts cache entries with mtime older than `TTL_DAYS` (7) globally. Without it, entries only evict per-key on `check` reads of the same prompt, so the `apex-discovery-cache/` directory grows unbounded when prompts are not re-issued. Wired into `create-session.sh` startup alongside `sweep-orphan-artifacts.sh`. HEAD-divergence eviction continues to fire per-key on read (cheap; touches git only when the prompt is checked).
